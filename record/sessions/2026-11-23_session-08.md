## 1. 缺陷 D 现状（已核实，行号以修复前代码为准）

- 入口存在：`public/lib/pages/knowledge.js` 的「记录认识」调 `ctx.api.createStatement({ topicId, text, nature, createdBy: "human", ... })`；后端 `services/knowledge-base.ts` 的 `createKnowledgeStatement` 产出 **pending** 知识项（`payload.cardId` 缺省、`origin.sourceClass = human_statement`、`contentType = claim`、`review.status = pending`）。
- **断点 1**：待审列表 `kzPendingItems(state, cardIds)` 用 `(!cardIds || cardIds.has(e.payload.cardId))` 过滤。人工陈述**无 `cardId`** → 选中文献（传入 `cardIds`）时被滤掉。
- **断点 2**：列表项 `“<button class="kzq-kitem" data-iid ... data-cid>”`；陈述 `cardId` 为空 → 点击走卡片详情路径时无卡可开（中栏只会渲染卡片面板，陈述无处可看）。

## 2. 修复（不改后端科学语义、不改卡片审阅流程、不造假入口）

| 位置 | 改动 |
| --- | --- |
| `knowledge.js` `kzPendingItems` | 收紧为**只收卡内知识项**（要求 `e.payload?.cardId`）。 |
| `knowledge.js` `kzPendingStatements`（新增） | 收**无 `cardId` 的 pending 陈述**，不被文献/卡过滤。 |
| `knowledge.js` `hasPendingStatements`（导出） | 供 `app.js` 判断无文献时是否仍渲染分项面板。 |
| `knowledge.js` `knowledgeQueueHtml` | 「知识项待审」**分区并列**：`卡内知识项待审` / `人工陈述待审`（陈述按钮 `data-cid=""`）。 |
| `knowledge.js` `knowledgeWorkspaceHtml`（cards 面板） | 新增**人工陈述待审**独立审阅区，逐条复用 `kzItemHtml` 详情（查看/确认`ki-ok`/待补`ki-info`/排除`ki-out`/改值`ki-save`/回查旧版`ki-old`）。 |
| `app.js`（渲染闸门） | 无文献但存在待审陈述时仍渲染分项面板（陈述不依赖卡片）。 |
| `styles.css` | 新增 `.kzstmts` 容器样式。 |

- 点击人工陈述：既有 `kzq-kitem` 处理器在 `data-cid` 为空时即落到无卡路径（`ui.kzPanel="cards"`、`cardOpen=null`），中栏渲染人工陈述区后 `scrollIntoView` 命中该 `.kitem` —— **无需改事件处理器**。
- 确认/改值复用**既有**入口：`reviewKnowledgeItem(iid, { baseRevision, decision, basis })` 与 `updateKnowledgeItem(iid, { baseRevision, patch, reason })`；后端对 `human_statement`（`modelSourced=false`）不要求引文锚点，可正常确认。
- 确认后离开 pending → 进入主题「当前认识」候选池（`kzThemesHtml` 按 `topicIds` + `review.status==="confirmed"` 过滤）。
