- **返工项 1（必修）· 回取原件的 `content-disposition` 未转义 → 畸形/CRLF 文件名致 500**：
  - 位置 `sciworkbench/server.ts:483` `sendBinary`（配合 `:749` 用**用户上传原名** `meta.fileName`）。
  - 问题（实测）：文件名含 `"` → 畸形头；含 `\r\n` → Node 拒绝写头，`GET /api/originals/:id` **整体 500**，该原件从此不可回取。

- **返工项 2 · 方案页二进制上传未处理 409 重复**：
  - 位置 `sciworkbench/public/app.js:2392` `proto-upload` 二进制分支。
  - 问题：同一 PDF 二次作方案上传，后端 `assertUniqueHash` 抛 409 → 整段报错；而同函数**文本分支**（`api.uploadProtocolSource`）已有 `e.status===409 && e.details.existingAssetId` 复用处理，体验不一致。
  - 核实既有约定：二进制 `importFile`（`/api/import/file` → `importParsedFile` → `assertUniqueHash`，`services/app.ts:64`）与文本 `uploadProtocolSource`（`services/experiment.ts:289` → 同一 `assertUniqueHash`）**共用同一 409 语义**：`{ existingAssetId, existingName }`，均指「同字节原件已存在」。故按**同口径静默复用**（不提示「已作为资料存在」，与文本分支一致）。
  - 修法：二进制分支加 `try/catch`，`409 && e.details?.existingAssetId` → `assetId = e.details.existingAssetId` 并 `setStatus("原件已归档：定位已有原件，继续解析")` 继续解析，其余 `throw`。
