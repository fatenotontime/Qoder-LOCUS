## S05-T3 · E1-3 commitState 单一写入边界（E1 判据齐备）

### 期间发现并修掉的产品缺陷（由新测试暴露）

1. `commitKnowledgeChunkNow` 以 `prepared?.index ?? -1` 定位块 → 回执重放路径（prepared 为空）抛 422「块不存在…第 undefined 块」。改为显式 `index` 入参。
2. 正常跑完的循环未置 `job.status`，job 永远 `running` → 前端无限轮询。收尾补 `done`。
3. `localIds(relRaw,"relations")` 要求 relation 带 `localId`（合同 schema 没有）→ 合法批被整块拒收。改为只校验 `fromLocalId/toLocalId` 齐全。
4. relation 端点写卡 localId 时**构建期**崩溃（「relation 端点无法解析」）→ 校验期新增可寻址集合与「多项卡歧义」拒收规则，`buildKnowledgeBatch` 为单项卡登记别名。
5. 最后一块重试成功后 run 仍停在 `partial`（状态与块结果不一致）→ 重试收尾按块集合回推 `completed`。
6. 测试基础设施缺陷：故意不回复的门控 fetch 会让 `postChat` 的 120s abort timer 挂住，整文件耗时 ≈120s；`restore()` 释放未答复挂起为合法空批后降至 689ms（`ai-stream` 因含退避与重启生命周期为 ~12s）。
