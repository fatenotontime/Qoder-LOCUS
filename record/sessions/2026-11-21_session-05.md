## S05-T3 · E1-3 commitState 单一写入边界（E1 判据齐备）

### 实施（`sciworkbench/server.ts`）

- `createApp` 内新增 `commitState(changeFn)`：promise 串行队列；changeFn 在队列执行时读**最新** state；**`store.save` 成功后才发布内存 state**；单笔失败被队列吞掉错误继续下一笔（不挂死）。
- HTTP 分发：写方法（POST/PUT/PATCH/DELETE）整体包进 `commitState`；GET/HEAD/OPTIONS 直通只读已提交 state（不落库、不排队）。启动恢复保存也改先存后发布。
- 49 处主模式 `state = r.state; await store.save(state)` → `await store.save(r.state); state = r.state`；特殊写点逐一改造：reviewCard/batchConfirm/cancelChat/retryChat 用局部 next；reviewTable＋registerImpact 一笔累积后保存；atResult 多附件在局部 `next` 累积（中途失败不发布半个）。
- 后台 job 全部「模型调用在队列外、写回在队列内对最新合并」：
  - 对话：取消检查移入队列内；失败标 failChat 也入队（保存再失败不崩进程，job 仍记错）。
  - 知识抽取：`persistChunk` 本身不入队（retry-chunk 路由已在队列内），后台 `onChunkCards` 用 `commitState` 包裹；收尾保存改 `commitState((latest) => store.save(latest))`。
  - 文献 AI / 方案解析 / 方法推荐：写回整体入队（409 丢弃语义保留）。
  - 影响评估：saveState 回调入队且**只合并本条影响记录**（其余实体保持最新）；已被标 stale 的不被旧评估复活。
  - OCR：追加入队，基于 latest.ocrs。
