## 1. 本轮已完成：表识别的结构修（不是又一轮症状补丁）

### 1.1 根因（对照截图）

截图右栏 `50 行 × 10 列`、重复的 `Unit/Initial concentration` 列、半空行，来自三个**隐含假设**被真实文件证伪：

| 隐含假设 | 真实文件（EnzymeML/DaRUS 导出） | 后果 |
| --- | --- | --- |
| 一个文件 = 一张表 | `Kinetic Models.csv` 多表叠放（空行分隔）；`Documentation.csv` 散文+列表 | 跨表串行的垃圾表 |
| 两级表头 = 两行拼接 | 合并单元格：组名只写在组的首列（`Protein` 后两列空） | 组名丢失 → 重复 `Unit` 列、语义歧义 |
| 表体每行都是测量行 | `Data.csv` 每个时间块以 `0,Time [min],…` 标记行开头 | 10 行标记混入 40 行测量，视觉"半空行" |

### 1.2 改动（`services/app.ts` / `store.ts` / `server.ts` / `public/*`）

- `splitBlocks`：按**首列单格标题行**与**全空行**切表块；非首列单格行视为列表残行（不作标题、不入表体）。
- `autoHeaderLevels`：两级表头须符合**合并单元格语义**（第二级在首级空缺处有续列），否则单级——修 `Documentation` 首行数据被误吞为表头。
- 列名：两级时**组名前向填充**（`Protein/Name`、`Protein/Initial concentration`、`Protein/Unit`…）。
- 宽度：按**首/末非空列**裁剪（去首尾全空列占位）。
- `markerRows`：块标记行（非空格数 ≤ 表头一半且集中前缀列）**保留原行、仅标注**；右栏淡显 + 计数 `50 行（40 数据 · 10 标记）`。
- 多表块 → 多张 `MeasurementTableRecord`（名字带块标题/序号），右栏**表块切换器**；`parseCsv` 保留全空行作块边界。
- 新增 `scripts/corpus-check.ts`：真实语料逐文件结构回归（列名/行数/标记/占位），解析层改动的必跑验收工具。

## 2. 回顾：S02-T4 → T8 反复修复的共同结构原因

| 轮次 | 症状 | 当时的补丁 | 被证伪的隐含假设 |
| --- | --- | --- | --- |
| T4→T5 | AI 非严格 JSON 即败、无重试、原响应不留 | 容错阶梯+重试+留存 | 远端模型=本地函数（输出格式/可用性 guaranteed） |
| T5 | CSV 分隔符/BOM/TSV 误解析 | 判定+剥离 | 文件=干净逗号 CSV 文本 |
| T6 | 两级表头/尾空列/误吞数据行 | 合并+r0 guard+裁剪 | 表头在首行、矩形稠密单表 |
| T7 | 超时写死、超时不重试、无进度 | 可配超时+上限重试+job | 请求=瞬时同步调用 |
| T8 | 组名丢/标记行混入/多表串行 | 分块+合并单元格语义+标记行 | 一文件一表、空列=独立列、表体全为测量行 |
| T5 | 连点/丢编辑/错误弹窗 | runBusy/脏检查/内联 | 操作=瞬时、UI 无操作状态机 |

**共同结构原因（两条）：**

1. **边界处没有显式契约，用启发式自动猜。** 解析层猜格式、AI 层猜模型行为、UI 层猜操作时序。
   每来一个真实文件/真实模型/真实点击就证伪一条假设 → 加一条启发式 → 下一轮再证伪。补丁彼此叠加成"启发式堆"。
2. **验收用合成单测 + 单个真实文件，不用语料契约。** 单测编码的是实现自己的假设，故"全绿"≠"对真实数据正确"
   （T6 自认只测过 1 个 csv；T8 截图再次证伪）。

**反证（骨架没问题的部分）：** 三业务路径分离、修订历史、原件 hash/超限拒绝、回查网络、Store 接口与 v2→v3 迁移、
AI 独立任务+审计——这些在 T4→T8 全部轮次中**从未需要返工**，且本轮证明流程全部通过。问题集中在**边界契约缺失**，不在分层与领域模型。

## 6. 小结：规避补洞式开发的推进方式调整

1. **契约先于启发式。** 边界（文件格式/模型行为/操作时序）先写显式契约与 profile，启发式只允许在 profile 内；
   新启发式必须先有落库失败夹具（red-first），杜绝"先猜后补"。
2. **语料即验收。** 真实样本语料 + 结构期望是验收定义；每轮提示词与交付必须附 corpus 结构 diff，单测全绿不再等于通过。
3. **修假设，不修症状。** 症状先归因到 §2 假设表；一次提交修一条假设（结构因），同因症状批量闭合；禁止逐症状提交。
4. **丰富每轮提示词（模板）：** 目标 / 完整验收流程 / 语料证据要求 / 禁止范围 / 已知反例与缺陷登记 / 记录要求。
   用户侧每轮给"验收流程+反例"，agent 侧每轮给"结构 diff+缺陷登记"，替代"功能清单+测试数"。
5. **架构信息同步先行。** `docs/architecture/01_DOMAIN_SCHEMA` 增 FORMAT_PROFILES 节、ADR-0005（解析模型契约化）先于代码更新；
   缺陷登记（D1/D2…）带归属调整项与轮次，不即修、不丢失。
6. **阶段门。** 设稳定化门：A1–A4 完成 + §5 流程通过 + 用户 review 后，才恢复 4B/4C；每门用户实测，不倒签。
