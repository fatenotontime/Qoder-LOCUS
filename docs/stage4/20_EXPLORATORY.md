## 重大问题 1：远端模型调用的健壮性与可诊断性不足（后端）

**复现**
1. 页面「AI 配置」填好 baseUrl/model/key；
2. 文献导入选 **AI** 抽取 → 远端模型返回了非严格 JSON（如未加双引号的键）。
3. 页面弹窗：`导入失败：模型 JSON 解析失败：Expected double-quoted property name in JSON at position 2233 (line 1 column 2234)`（与用户截图一致）。

**影响**
- 只要模型输出有任何非严格 JSON（未加引号键、注释、多余对象），整次导入**直接失败**，且无重试、无修复；
- 错误以**原始英文技术串**弹窗，用户无法判断是可重试/换模型/内容问题；
- **原始响应未留存**：`services/ai.ts` 无“原响应写入授权审计区”逻辑（grep 无 raw/留存），违反 03「原响应留存」契约，事后无法诊断“模型到底返回了什么”。

**证据**
- 编程式 stub 复现：返回 `{"cards":[{"rawText":"x","extracted":{"fields":{pH:"3"}}}]}` → 抛 `模型 JSON 解析失败：Expected property name or '}' …`；围栏/散文前后缀可解析，**非严格键失败**。
- `grep -n "retry|原响应|留存|raw" services/ai.ts` → 无命中。

**已确认良好（对照）**：失败是**原子**的——`state.assets` 不变（不写入半成品）。

## 重大问题 2：CSV/表格解析崩坏（图表处理）

**复现**
1. 实验数据流程导入真实 `EnzymeML_SLAC_pH5_5__Reactions.csv`（EnzymeML 导出，含**章节标记行**与**多行表头**）；
2. 右栏表格：表头变成 `Reactions | col2 | col3 …`，第一行数据是真正的表头 `ID | Name | Temperature value …`，下面 20 行几乎全空的 `r1…r19`。

**影响**
- SLAC 实验数据路径**不可用**：列名与数据全错位、行数虚高（`created`=21，真实数据仅 1 行）；
- 用户无法核对数值/单位/行列（正是实验数据路径的核心动作）。

**证据**
- `parseCsv` 输出：22 行；`row0=["   Reactions","","",…]`（章节行被判为表头）、`row1=[ID,Name,…]`（真表头成了数据行）、`row2=[r0,…]`。
- `importMeasurements` 结果：`columns=["Reactions","col2"…]`、`rows.length=21`、`created=21`。
- 根因：无表头识别/噪声行过滤；`parseCsv` 仅按“非全空行”保留，章节标记行（`   Reactions,,…`）被当表头。

## 重大问题 3：请求无进度与重复点击保护；导航丢未保存编辑（前端行为）

**复现**
- 3a 连点「导入」两次（同内容）：后端**两次都成功**，产生**重复材料**。
- 3b 发起 AI 导入（耗时长）期间：**页面无任何“处理中”指示**，按钮**不禁用**，用户只能猜测。
- 3c 在右栏编辑证据卡字段（改了但未点“保存”）后切到另一材料/课题：**编辑被静默丢弃**，无提示。

**影响**
- 重复点击 → 重复素材/重复卡（“21 项不代表 21 次测量”类问题的同源）；
- 长请求无反馈 → 误判卡死、重复提交；
- 未保存编辑静默丢失 → 用户以为已保存，页面/后端/预期三者不一致。

**证据**
- 3a：同内容导入两次 → `assets 2 / tables 2`（应拒重，LIT07 未接）。
- 3b：`public/app.js` 导入处理器无 `disabled`、无 loading 状态（源码核对）。
- 3c：`renderAll()` 在切换材料时整块 `innerHTML` 重建右栏，DOM 输入值未落库即被覆盖（源码核对）。
- 对照：**并发 12 请求全部落盘（assets=12）**，说明问题在“重复点击语义”而非服务端丢写。

## 页面/后端/保存 一致性核对
- 重复导入：**页面=后端=保存**（都显示 2 份）——一致但都错（不符合用户预期）。
- 表格崩坏：**页面=后端=保存**一致，但语义错误。
- AI 失败：页面弹错、后端 502、**保存不变**（原子）——一致且安全，唯缺诊断信息。
- 未保存编辑：**页面 DOM 值 ≠ 后端/保存**——不一致（切走即丢）。

## 修复顺序建议（待用户确认后再动手，不与新功能混提）
1. **请求层公共面（覆盖 1/3）**：所有写操作加**处理中指示 + 按钮禁用（防连点）**；统一**友好中文错误**（保留原始串到审计区），失败可**重试**。
2. **AI 健壮性（重大1）**：JSON 提取放宽（去围栏/散文、常见未加引号键修复）+ 一次受限重试 + **原响应留存到授权数据区**（去认证头）。
3. **CSV/表格（重大2）**：表头识别（跳过章节标记/合并多行表头）+ 去空行 + 保留原结构；**导入按 hash 拒重**（LIT07）；非 CSV 明确拒绝。
4. **导航未保存编辑保护（重大3c）**：脏检查 + 切换/刷新前提示（或轻量自动暂存）。
5. 相邻项 A3–A8 随相关步骤收尾。
