# 阶段0 · 数据流走查（修正版）

> 本文是对"导入一份实验材料后…"系列问题的**修正版**回答，取代此前把三条路径合成一条、把两事件合成一个、把回查写成单链的说法。
> 对齐材料：10_PRODUCT_DESIGN_NARRATIVE §三/四/五/十/十二/十三/十七，03_DOMAIN_RUNTIME，02_CURRENT_DECISIONS（LIN/OCR/LIT/EXP 组）。

## 0. 三条铁律（先立后答）

1. **先分路径**：文献建库 / 方案解析 / 实验数据核对是**三条不同业务路径**，入口材料、主对象、审阅动作都不同，不能合并成"导入材料"一条流水线。
2. **先分事件**：**导入公开实验数据** 与 **用户执行一次实验** 是**两个不同事件**，产生不同对象，不得互相套用。
3. **回查是网络**：不同对象类型有**不同的回查链**（LOCUS 内部结果 / 作者外部结果 / 文献数值 / 实验背景 / 原始测量各不同），不是一条固定串联链。

## 1. 三条业务路径（各自的对象与审阅）

| 路径 | 入口材料 | 主对象 | 审阅动作 | 定位方式 | 验收 |
| --- | --- | --- | --- | --- | --- |
| **A 文献建库 LIT** | 文献 PDF / 网页 / 题录 | SourceAsset(文献) + **EvidenceCard** + NameMapping/Comparison | 提卡 → 人审：**核对(是否忠实原文) / 课题重要程度 / 按任务采用** 三维分开；补卡、批审需先展示共享条件 | 页序/区域/表号行列/图注 | T10–T16 |
| **B 方案解析 EXP/ARC** | 方案文件 / 手填 / AI 组织 | **ProtocolRevision** + RecordTemplateRevision（+ 可跳过执行条件选项卡） | 人工确认模板后复用；图与表单**同一份语义数据** | 步骤/操作稳定身份 | T03/T06 |
| **C 实验数据核对 OCR** | 仪器原始文件 / 谱图 / 表格 / 纸记录 | SourceAsset(数据) + **Measurement** + 执行记录骨架 | 识别草稿 → **原图区域回查** → 人工修订 → 确认稿 | 原图区域/字段 | T09 |

> 三路径**共用同一领域模型**（03 的对象表），但**不是同一条流水线**：文献产证据卡，方案产 ProtocolRevision，实验数据产测量/记录。此前混淆就发生在这里。

## 2. 两个事件（同一次"导入"结果不同）

| | 事件 A：导入公开实验数据 | 事件 B：用户执行了一次实验 |
| --- | --- | --- |
| 性质 | 引入**外部材料与证据** | 产生**用户自己的执行事实** |
| 产出 | SourceAsset（数据原件）；可"重构"的方案（**标重构，非作者原始计划**）；作为**公开证据**的测量 | **Execution/Session**（实际过程层）；样品身份（母样/分样）；独立 Measurement；append-only 事件；偏差/补录 |
| 不产出 | **不产生**用户执行记录；**不新建**用户样品；**不宣称**用户原创科研 | 不把公开材料冒充用户成果 |
| 作者外部图 | 是"**外部成果提交示例**"，不是系统内置答案；第 3 步由用户显式提交 | — |
| 可追溯 | 缺原始处理链时**只到文件级**，显示缺口 | 到执行/样品/测量实际层 |

**关键**：即使面对同名文件，A 走"来源/证据"，B 走"执行/事实"，结果对象不同。此前把 B 的记录/测量硬套到 A，是错的。

## 3. 用户如何审阅（按路径不同）

- **路径 A**：从材料提证据卡，逐卡三维护；确认/待补/排除/跳过明确选；关键数值修改须原因；定位可回查；后台 AI 不替换人正在审的版本。
- **路径 B**：方案首次引用时 AI 解析出专用记录模板，**人工确认后复用**；新方案比较模板变化，不让字段漂移；通用记录页作失败兜底。
- **路径 C**：识别草稿对照原图逐格复核；两次识别冲突标 `?`，不交给结构模型裁决；失败/空输出**不产生**已确认态。

## 4. 分析实际引用哪些版本

经**上下文地图**选范围（主课题→**必选子问题**→直接数据及其来源方案/记录为核心，相关候选可取消），确认后冻结为 **ContextSnapshot**（对象及 revision、实际发送片段/摘要、目的、提示词版本、快照 hash）。引用一律**指固定 revision，不是 latest**；UI 选中项与真实发送内容可核对。

## 5. 报告一个数值怎样回到原始材料（**按类型，多条链**）

点一个值，回查**该值所属类型的那条链**；这是**图/网络 + 按需展开**，缺一段就显示缺口。

| 值/陈述来自 | 回查链原型 |
| --- | --- |
| **LOCUS 内部处理结果** | 数值 → ResultRevision → **Run**（输入快照/方法/参数/软件版本）→ 上游结果或原始表（列/单元/图系列） |
| **作者外部结果** | 数值 → ResultRevision（标"外部提供"）→ 作者来源文件/图；**方法不足时只到文件级**，不硬造 Run |
| **文献数值/插图** | 数值 → **EvidenceCard** → 定位（页序/区域/表号行列/图注）→ SourceAsset(文献)；**不经过 Run/Measurement** |
| **实验背景/判据/目标** | 陈述 → Topic/Subquestion 及来源（文献/计划）；**根本不回**到某次测量 |
| **原始实验测量** | 数值 → Measurement → SampleState → Execution → ProtocolRevision |

> 此前写成"数值→结果→Run→原始表→执行→样品→测量→原件"这一条死链，是错的。

## 6. 数据后来被更正 → 哪些需要复核

按**变更类型**分流（确定性传播 + AI 语义评估各司其职）：

| 变更 | 复核范围 |
| --- | --- |
| 确认表中**一个数值** | 命中真正引用它的分析/图表/报告块（不遗漏多报告） |
| **单位 / 样品归属** | 相关处理、比较与解释复核，保留旧输入 |
| **方法 / 参数 / 代码** | 建**新 Run** 与新产物；旧 Run 可还原；不覆盖旧报告 |
| **研究目标 / 判据** | 复核解释/结论；数值无理由不强制重算 |
| **标题 / 备注** | 通常不重算、不误报 |

处理：保留历史（旧 v 仍可复现，并解释"基于当时材料"）；最新界面标**过期/待复核**；人工选重算/保旧/确认理由/撤回，记理由与版本，不许"全部确认"；**缺依赖或模型失败不得解释成"无影响"**。

## 7. 为什么"只为下次实验新建方案"不该让过去结果失效

区分**三类事件**：**新计划 / 历史事实更正 / 重新解释**。

- 方案描述**意图**，记录描述**事实**；每次执行**固定引用当时的方案版本**。
- 为下次实验新建方案版本 = 产生**新意图**，不回写、也不追溯性改变过去那次执行**实际采用**的条件。
- 因此只要旧执行仍准确引用旧方案，过去的测量就**不该凭空失效**。只有**旧记录被更正**，或用户**明确用新条件重评旧结论**，才建立复核任务。

这就是版本模型与双链（数据链 + 科学依据链）的意义：**新方案不回写旧执行**；"旧结果可复现"与"旧结论仍适合当前判断"是两个判断，但**新建计划本身**不触发对历史的下游作废。

## 8. 一页图

```text
                ┌─────────── 三条路径 ───────────┐
   文献PDF ─▶ A 文献建库 ─▶ EvidenceCard ─▶ 审阅(核对/重要/采用)
   方案文件 ─▶ B 方案解析 ─▶ ProtocolRevision ─▶ 模板确认复用
   仪器/纸记录 ─▶ C 数据核对 ─▶ Measurement + 记录骨架 ─▶ 原图回查·修订·确认

                ┌─────────── 两事件 ───────────┐
   公开数据导入(事件A) ─▶ 来源/证据（不宣称用户原创、不建执行）
   用户做实验(事件B)  ─▶ Execution/Session + 样品 + 测量 + 事件

                ┌─────────── 回查网络(按类型) ───────────┐
   内部结果 → Run → 原始表/上游结果
   外部结果 → 作者来源(可只到文件级)
   文献数值 → EvidenceCard → 文献定位
   实验背景 → Topic/子问题（不回测量）
   原始测量 → SampleState → Execution → ProtocolRevision

                ┌─────────── 变更传播 ───────────┐
   数值/单位/归属 → 命中的分析·图·报告块复核
   方法/参数/代码 → 新 Run（旧可还原）
   判据/目标     → 解释复核（数值不必重算）
   新计划 ≠ 历史更正 ≠ 重新解释
```
