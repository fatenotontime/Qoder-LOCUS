## 1. 产品定义：不是另一个文件柜，而是科研工作台的知识读取层

LOCUS 知识库汇集“文献说了什么、我们计划做什么、实际做了什么、测到了什么、怎样处理、据此作了什么判断”，让用户围绕研究问题阅读、比较、回查，也让程序和 AI 在明确范围内读取同一份有来源、有版本的数据。

它不是全库内容的自动摘要，不等于向量数据库，也不要求把每份材料、每个表格单元格都变成知识卡。

### 1.1 三种组织尺度

1. **资料层面：可复用资料目录。** 论文、附件及通用方法可被多个课题引用；未归属资料留在资料目录，不自动进入所有课题。
2. **工作层面：课题知识空间。** 以课题和子问题组织文献证据、实验过程、数据、比较、结论；这是日常使用的默认范围。
3. **任务层面：可追溯知识快照。** 为一次比较、一次 AI 请求、一次 wiki 导出固定具体内容和规则；后续修改不改变旧任务的输入。

同一论文可以服务多个课题，但“被某课题采用”“被排除”“对某问题有什么意义”分别保存，不污染其他课题的判断。

### 1.2 用户应得到的体验

- 做正常科研记录时，知识关联和检索内容随之更新，不要求再去另一个库重复录入。
- 打开课题，能看见已有证据、相互矛盾的结论、实验进展及真正阻碍下一步的缺口。
- 从结论、图表数据点或 AI 引用，可以回到当时使用的证据，而不只是打开一篇论文首页。
- 没有配置 AI 仍可归档、人工整理、检索、比较已映射数据和生成模板化 wiki。
- AI 帮助整理、发现与草拟，不替用户决定事实、替代证据或默认向外发送整个项目。

## 2. 现状与设计新增的界线

| 能力 | 当前核查结果 | 本设计需要补齐 |
| --- | --- | --- |
| 论文 / 附件 / 知识卡 | 已有分开的对象、人工审阅、多段引文 | 从文献卡扩展为跨模块知识读取层 |
| 方案 / 执行 / 样品 / 测量 / 数据表 | 已有实际数据模型和部分固定引用 | 统一查询、关联粒度、知识表达及来源解析 |
| 分析 / 报告 / 对话 | 已有任务、结果、报告块、上下文对话与人工采纳路径 | 统一上下文契约，避免把摘要、聊天或报告当新独立证据 |
| 字段映射 / 比较 | 已有命名映射、比较快照 | 字段级值与单位绑定、语境规则、规则版本、可比性判断 |
| ID / revision / 历史 | 多种对象已有，但实现不统一 | 统一固定版本解析；无完整历史的旧数据不能伪造历史 |
| 导出 / 恢复 | 已有 DOCX、追溯包和含状态 JSON 的全库备份 | 分析就绪 JSON/CSV、Markdown wiki、任务级内容包 |
| 搜索与展示 | 已有按课题/文献/审阅状态筛选与引用网络 | 跨模块查询、主题阅读、可回查比较图表、wiki |
| 外部 AI | 已有服务端发送选定上下文 | 专用受限读取契约；不能把全状态接口当外部知识接口 |

### 2.1 不能沿用的乐观假设

- [卡片与比较模型](../../sciworkbench/store.ts#L79)中，字段、单位、条件是分开的数组/字典，不能天然一一对应。
- [比较实现](../../sciworkbench/services/app.ts#L540)按映射名称分组、比较字符串；“数值一致”并不等于单位和科学口径一致。
- [上下文解析](../../sciworkbench/services/analysis.ts#L63)大多读取当前对象；卡片版本使用审阅状态文字，表格摘录最多取前 30 行，不能作为通用完整数据冻结机制。
- [报告引用网络](../../sciworkbench/services/references.ts#L232)可显示固定版本说明，但建边按当前对象查找，不能据此声称旧实体已可完整读取。
- [存储加载](../../sciworkbench/store.ts#L618)有日常失败返回空状态与严格加载两种路径；新知识快照构建应采用显式失败语义，不能把加载失败当作“没有知识”。
- [文献导入](../../sciworkbench/services/app.ts#L43)目前有文本格式边界；PDF、原生表格文件等不能只因目标设计需要就视为已支持。

## 3. 总体结构：五层职责，一套权威数据

```text
既有工作板块
课题 / 文献 / 知识 / 方案 / 记录 / 分析与报告 / 对话
        │ 正常保存、人工确认或采纳
        ▼
① 原件与业务事实层
原件、记录、表格、已有版本、用户判断
        │ 按固定版本读取，不复制建立第二套业务事实
        ▼
② 知识表达层
陈述、数据集视图、字段映射、来源锚点、明确关系、缺口
        │ 检查来源、审核、范围和本次任务的可比条件
        ▼
③ 查询与任务快照层
跨模块检索 + 关系展开 + 选定范围 + 内容与规则冻结
        ├──────────┬──────────┐
        ▼          ▼          ▼
④ 人类视图      ④ 分析视图    ④ AI 读取视图
wiki / 卡片     比较表 / 图   JSON / CSV / 受限接口
        └──────────┴──────────┘
                   ▼
⑤ 使用结果与人工采纳
新判断 / 待验证事项 / 分析结果 → 草稿 → 人工确认 → 业务层
```

**层是职责，不是五套数据库或五个新服务。** 首版可以在现有进程与 Store 中完成，不引入消息总线、独立图数据库或向量数据库。

### 3.1 唯一权威如何落地

- 原始表格数值、执行事件、方案等继续由原模块维护；知识视图不提供独立的第二份数值编辑。
- 新增映射、人工补充的知识陈述、知识关联与审核记录属于新增持久化数据，有自己的权威写入入口。
- 从原模块提取的知识项固定引用来源对象版本；用于查询的字段副本只是可重建投影。
- 导出快照保存当时的内容副本是历史证据，不是可编辑的另一套当前真相。
- wiki 中的“修改”回到对应业务对象或人工说明编辑器；生成后的 Markdown 不反向覆盖数据库。

## 4. 从哪些板块取信息，哪些动作必须由人完成

以下是目标接入矩阵；“自动”指用户完成正常业务操作后，在本机执行确定性整理，不等于自动调用外部 AI。

| 板块 | 进入知识体系的信息 | 可自动完成 | 依赖用户的操作 | 明确禁止的推断 |
| --- | --- | --- | --- | --- |
| 课题 / 子问题 | 研究目标、问题层级、任务范围 | 建立目录、归属链接、覆盖情况 | 定义问题、确认材料归属与当前重点 | 从标题猜出研究假设或把同名课题合并 |
| 文献整理 | 题录、附件角色、许可、原文、导入来源 | 查重、登记 hash、索引可解析文本 | 导入资料，补充必要题录/许可，选择提取范围 | 收藏即视为已阅读、已认可或独立证据 |
| 领域知识 | 原文陈述、方法、解释、数据摘录、人工注释 | 基于明确请求生成提取草稿、验证引文匹配、组织待审队列 | 核对提取、修正类型和条件、采用或排除 | 匹配到原句就视为结论获得支持 |
| 实验方案 | 方法步骤、预期条件、终点、记录模板 | 建立方案版本与来源关系 | 确认方案及模板，选择执行版本 | 把计划温度、预计时长当作实际测量 |
| 执行记录 | 实际步骤、暂停、偏离、失败、手写转录 | 链接实际执行与固定方案、列出显式差异 | 记录实际情况、确认 OCR、解释异常 | 把缺记录当作没发生，把未填值当零 |
| 样品 / 测量 / 数据表 | 样品状态、独立测量、仪器输出、重复与时间序列 | 表格解析、类型检查、按已确认规则映射 | 确认列含义、单位、样品关联、重复类型及必要更正 | 把技术重复当生物重复，自动剔除异常值 |
| 数据分析 | 输入范围、实际方法、参数、结果文件、计算过程 | 建输入输出关系，记录是否缺复现要素 | 选择比较目的、提交真实方法与参数、确认结果解释 | 有结果文件就宣称已验证算法或可复现 |
| 报告 / 人工判断 | 观察、假设、解释、待验证事项、引用 | 按引用挂回原证据，显示失效/更新提醒 | 编辑和确认结论、声明适用范围 | 报告再次引用自身而增加独立证据数量 |
| 上下文对话 | 明确采纳的问题、解释、行动建议 | 保存对话与实际发送范围；拟定候选知识 | 点击保存候选/采纳，选择目标与知识性质 | 默认把全部聊天写入正式知识，或把模型建议当观察 |

### 4.1 人工依赖应集中在三类决定

1. **输入与归属：** 资料来自哪里、研究什么、这次处理哪些内容。
2. **语义与事实确认：** 原文是否支持提取、单位条件如何理解、实际发生了什么。
3. **使用与对外发送：** 采用哪些证据、按什么口径比较、允许发送哪些信息。

人工保存的实际测量不再被要求重复做一次“知识库确认”；复用原模块的确认记录。AI 推导的额外语义、陌生映射、OCR 模糊项仍需单独确认。批量确认须显示共同规则和例外项，不能用一个总开关掩盖异常。

### 4.2 文献究竟提取什么：提取可复用的研究单元

抽取对象不是“每段写一句摘要”，而是“某对象在某些条件下，采用什么方法，得到什么观察，作者据此怎样解释，又承认什么限制”。不是每篇文章都具备所有类型，也不为凑齐结构生成内容。

| 文献内容 | 重点位置（仅作查找线索） | 提取成什么 | 后续用途 |
| --- | --- | --- | --- |
| 研究问题与适用范围 | 摘要、引言、研究目标 | 作者研究的问题、对象与边界 | 判断是否与当前子问题相关；不自动替代用户的课题目标 |
| 对象与实验设计 | 方法、材料、补充材料、表注 | 物种/材料/系统、处理与对照、分组、样本量及重复含义 | 绑定观察的实验上下文，判断比较口径 |
| 方法与条件 | 方法、图注、表注、结果中的局部限定 | 步骤、仪器、方法版本、温度/pH/时间/浓度等显式条件 | 复用方法、解释差异、生成有来源的方案草稿 |
| 定量与定性结果 | 结果正文、表格、图注、补充数据 | 带对象、条件、指标、原值/限定符、单位、误差/统计口径的观察项 | 筛选、比较、绘图和计算 |
| 术语与操作定义 | 方法定义、命名说明、注释 | “指标是什么、分母是什么、如何测得”的定义 | 为字段映射提供依据，不只收集别名 |
| 作者解释与假设 | 讨论、结论，或结果中的解释句 | 与所解释的观察分开的陈述及依赖关系 | 形成可复核的解释链，与后续研究对照 |
| 负结果、例外与局限 | 结果、讨论、补充材料 | 哪些条件下不成立、作者承认的限制、尚未验证的部分 | 防止只沉淀正向结论，限定外推范围 |
| 转引与研究线索 | 引言、讨论、参考文献 | 被转述的主张、转引者、被引来源（能确定时） | 保留线索但不计为新增独立观察；提示取得一手来源 |

摘要中的结论可先成为候选，但没有结果/方法证据时不能装成完整实验记录。章节名不是知识性质：讨论中也可能报告观察，结果段也可能含解释，应按具体句意与证据分类。

表格提取必须带表头层级、脚注、单位、组别和统计量说明。图中的点值只有在确实完成图像/数据读取后才可入库，并标记估读方法和误差；首版未支持图像数值提取时，保留图引用及明确写出的数值，不从趋势图补造精确数据。

一次提取保存覆盖范围：选了哪些附件/段落、哪些成功处理、哪些未解析、哪些尚待查证。“本次未找到温度”与“整篇文献未报告温度”是两种不同结论；只有在声明范围中完成核查才能使用后者。

### 4.3 从原文到沉淀的实际流程

1. **选择问题和材料。** 用户指定目的与附件；未选择附件不能隐式变成发送全部附件。
2. **定位候选研究单元。** 在所选范围内寻找与问题有关的结果、方法、条件和限制，保存附件 ID、段落位置及处理范围；不是先自由摘要再补引文。
3. **关联结果与上下文。** 利用原文明确的组名、表号、步骤号或引用说明寻找适用方法/条件；跨段或跨附件的对应关系不确定时形成待确认关联，不取最近的温度随意继承。
4. **输出结构化候选。** 一个可读卡片可包含若干观察项、作者解释、条件上下文、来源和关系；它们仍作为待审内容保存。
5. **程序校验与重复识别。** 检查类型、数值限定、单位、关系引用、出处候选和同一任务重试；语义疑似重复只提示，不自动吞掉不同实验。
6. **人工核对。** 对照相应原文核对数值、条件适用范围、观察/解释区分；可按组确认，例外项单列。科学内容更正后创建新版本并使相关审核待复核。
7. **加入知识主题。** 已确认项按指标、对象和问题组织，加入比较、限制与使用记录；某课题是否采用仍独立决定。
8. **形成主题判断。** 用户或 AI 可以提议“现有证据支持什么、还不能推出什么”，作为新的派生陈述保存，保留依据并经人审；不是每次展示时临时生成一句无来源总结。

“入库”包括待审候选的持久保存；“已沉淀”指其内容、上下文和出处已按相应用途核对，可以被检索、重用且保持知识性质。已确认假设可以作为假设沉淀，不因此成为事实；未确认项只在审阅/探索范围显示。

## 5. 知识如何表达：不是把所有东西压成一张大卡

### 5.1 三类主体，四类辅助记录

| 类型 | 职责 | 粒度与来源 |
| --- | --- | --- |
| 陈述 / 分析项 | 可阅读、可引用的一条有范围的主张，必要时带数值 | 一张知识卡可以有多项；报告块、实际观察、人工判断也可作为来源 |
| 数据集视图 | 可逐行分析的数据及列定义 | 引用固定表格版本与选定范围；不把每个单元格实体化为卡片 |
| 比较结果 | 指定问题下对多个项或数据集的比较 | 固定输入、规则、排除项、计算及未知项 |
| 来源锚点 | 定位当时的材料 | 原件 hash、对象版本、引文/区域/表格单元格 |
| 映射规则 | 原始表达如何对应标准含义 | 标准字段 ID、别名、语境、换算、审核、规则版本 |
| 知识关系 | 记录对象间是什么关系 | 来源、属于、支持、反驳、派生、使用方法、替代、待验证 |
| 审核与缺口记录 | 谁确认了什么，以及还不知道什么 | 针对具体字段或陈述，不是一个模糊总分 |

这是一种统一读取契约，不要求用同一个物理表存储所有实体。

### 5.2 一条陈述至少表达什么

- **身份：** 稳定 ID、内容版本、创建/修订信息；改标题不改身份，重新提取不能仅凭标题或文本相同就覆盖。
- **内容：** 人可读陈述、对象、条件和适用范围；数值项有指标、原值、单位及统计口径。
- **性质：** 观察、假设、解释、待验证、人工判断；方法/数据/思路等内容分类是另一维度。
- **出处：** 论文作者陈述、本地记录、历史文献重构、人工补充、模型草稿；“观察”不自动代表本地亲测。
- **审核：** 待审、确认、需补充、排除、撤回；确认提取忠实不等于证明普遍真理。
- **归属：** 被哪些课题、子问题或任务引用；审核与课题采用决定分开。
- **来源：** 固定版本引用与准确定位；一项可有多个支持片段，但要说明各片段支持什么。
- **未知：** 缺失、歧义、冲突、未测、低于检出限等原因；最后一种不是普通空值。

来源不强制是论文：人工实验记录本身可以是一手来源；没有论文不等于没有依据。无法回查的回忆或判断允许保存，但明确标为人工陈述，不包装成已验证观察。

### 5.3 数据集视图的最低契约

每列有稳定含义、数据类型、原始表头、单位和审核状态；每行绑定表版本及行身份/范围，适用时绑定样品状态、时间点、组别和重复编号。

- 连续值、类别、范围、不等式和“均值 ± SD”不是同一种类型，不能都用一个浮点数承载。
- 数值解析保留原字符串，计算使用明确类型；`0`、空值、未测、未报告相互不同。
- 大表保留表结构，按需产生比较行；原始数据 CSV 与规范化分析 CSV 明确区分。
- 首版回查以固定表版本 + 行列坐标为准，不声称能自动跨版本追踪任意插入、重排后的同一行；原模块需要跨版本编辑时再引入持久行 ID。
- 行坐标之外还要保存解析器版本和原件偏移映射；当前没有原件偏移的信息可回到应用内固定表版本，但不得声称已定位原始 CSV 的精确行。

### 5.4 关系必须有语义和依据

“同属一个课题”“被选为上下文”“来源于某文献”“支持某结论”不能用同一种边表示。

结构性关系来自明确业务字段，可自动建立；支持、反驳等科学判断需明确依据，AI 只能提出候选关系。同一来源拆成多张卡、经 wiki 或报告重复转述，不增加独立证据数；原始实验批次或证据独立性无法确定时只报告文档/来源数，不报告独立研究数。

### 5.5 知识数据与条件的关系：显式绑定，而不是一袋字符串

以“芦笋带成熟浆果的植株在干燥后漂浮 85 天，种子之后萌发”为例（真实出处见 §12），其中至少有两条知识：漂浮时长，以及后续萌发；它们的对象层次和发生阶段不同，不能共用一个不分阶段的 conditions 字符串数组。

建议的逻辑关系如下；这是普通 JSON 对象与 ID 引用即可表达的模型，不要求图数据库：

```text
文献 P + 附件 A + 原件版本/hash
  ├─ 片段 E1：方法/介质说明
  ├─ 片段 E2：处理条件、漂浮时长及后续萌发
  └─ 片段 E3：作者对真实海况的限制判断

研究上下文 C1：未干燥/新鲜状态 + 海水漂浮阶段
  └─ 观察 K1：对象=带熟果芦笋植株，指标=漂浮时长，原文=23 days
研究上下文 C2：干燥后 + 海水漂浮阶段
  └─ 观察 K2：同类研究对象，指标=漂浮时长，原文=85 days
后续上下文 C3：C2 所述材料的种子 + 后续萌发阶段
  └─ 观察 K3：萌发被观察到；萌发率、培养条件在选定片段中未报告

K1 + K2 ─经比较口径确认→ 比较 B1 ─派生→ J1：此例干燥处理对应更长的报告漂浮时长
K2 + K3 ─有范围的支持→ 判断 J2：该例与漂浮后仍有萌发能力相容
E3 ─作者限制 L1→ J2 向真实海洋传播的外推边界
```

“同类对象”的绑定不能冒充同一株样品的配对追踪；原文未给样品编号/重复数就不建虚构样品。C3 的前处理可追溯 C2，但不把海水条件继承成萌发培养条件。

#### 最小持久化结构

| 记录 | 主要字段 | 关系与作用 |
| --- | --- | --- |
| 知识项 K | ID/版本、陈述、性质、subject、predicate/metric、typedValue、contextRefs、evidenceRefs、审核 | 数值/性质及其适用上下文绑定；UI 卡片是若干项的阅读组合 |
| 条件上下文 C | ID/版本、所属研究单元、对象/组别、阶段、methodRef、conditionFacts、unknowns | 一组明确共同适用的条件可供多项引用，限定在原研究范围内，不是全库环境变量 |
| 条件事实 F（可内嵌 C） | 字段、原值、规范值（可选）、单位、适用对象/阶段、来源、获得方式、审核 | 每个温度/时间/处理条件本身也可回查；无须每个条件建一张用户可见卡片 |
| 来源片段 E | 附件 ID/版本、位置/范围、原文、匹配候选、定位状态 | K→E 标注支持哪个值/陈述；F→E 标注支持哪项条件，允许来自不同位置 |
| 关系 R | 两端固定版本、关系类别、依据、建立方式、审核 | 来源/前处理/比较/支持/限制/替代分开，AI 关联只作待审候选 |
| 知识主题 T | 稳定主题 ID、名称/定义、关联问题、确认的成员引用 | 聚合跨文献观察和判断；页面索引可重建，人工定义/成员调整有记录 |

首版在现有卡片及新增知识元数据中表达这些结构，具体集合命名待实施设计确定；不同时维护旧 fields 和新 observations 两套独立可编辑内容。原始模型提取输出作为审计输入保留，旧卡按其已有字段投影；不能确定绑定的旧字段显式标为未结构化，用户复核后才形成新版本。

#### 条件共享、冲突和缺失

- 同一实验组的多个指标可引用同一个固定版本 C；不同组共享方法，不等于共享全部实验条件。
- 公共方法条件需要证据说明适用范围，局部条件可更具体；两者冲突且无法确定优先级时列出冲突，不按“局部优先”静默消掉证据。
- 用户补入的温度要说明来自额外记录、人工回忆还是假设；补充来源不能写成论文原文。
- unknowns 挂到具体字段/范围，区分选定片段未提供、附件未处理、关联未确认、整篇核查未报告。
- 条件 C 修订产生新版本；旧 K 与 B 仍引用原 C，当前视图提示待复核，不能让共享条件更新悄悄改变所有历史结论。

## 6. 知识库如何逐步构建、更新和失效

### 6.1 初始化既有课题

1. 用户选择一个课题，系统只读盘点已关联对象，列出未归属、缺来源和不支持解析的材料。
2. 自动登记可确定的 ID、原件、关系及已有审核结果；不为填满字段调用 AI 猜测。
3. 对已确认的知识卡和结构化业务记录建立读取投影；新的字段拆分或语义解释仍可处于待审。
4. 用户按一个真实问题选择少数指标，确认首次映射与比较条件。
5. 系统生成第一版课题 wiki 和一份比较快照，展示未纳入项及原因。

### 6.2 日常增量更新

- 原模块保存后，相关对象的知识投影与检索记录标记待更新；由本地依赖关系确定更新范围，无需重新抽取整个课题。
- 初版读取时可直接从当前状态生成轻量投影；缓存使用输入版本、规则版本及投影器版本作键，缓存不是权威数据。
- 对需要模型的重新提取，只提示“有新材料/原件更新”，由用户发起或在明确授权的批次内执行。
- 后台任务固定输入；完成时追加结果或按基础版本进行冲突检查，不覆盖等待期间的人工作业。
- 内容、单位、条件等实质变化产生新知识版本并重新判断审核状态；标题、展示顺序等变化不自动制造“科学结论失效”。

### 6.3 不用一个状态机承担所有语义

- 提取状态：未开始 / 处理中 / 完成 / 失败。
- 审核状态：待审 / 确认 / 需补充 / 排除 / 撤回。
- 采用状态：按课题或任务决定采用 / 不采用。
- 新鲜度：当前 / 上游已更新、待复核。
- 可比性：按本次比较输出可计算 / 仅并列 / 不可比较及原因。

失败不等于无数据，确认不等于采用，未过时不等于正确；界面优先显示当前任务相关状态，不把所有标签同时堆给用户。

### 6.4 撤回与删除

用户撤回的陈述不进入新的正式比较，但旧快照显示“现已撤回”及当时内容，不静默改写旧结果。原件缺失、外部权限变化或主动删除导致无法回查时，返回明确状态而非跳到最新的近似内容。

如未来支持彻底删除敏感内容，删除权优先于完整历史保留：保留允许保留的墓碑说明，明确哪些旧快照失去内容，不能承诺已下载到外部的副本可自动收回；实际删除功能另行授权实施。

## 7. 跨卡比较与规则系统

### 7.1 从具体问题建立小词表

用户样例提供实际术语、wiki 层级和常见比较任务；系统据此维护课题词表，而不是预先建设全领域本体。

一条规则包含：稳定指标 ID、原始字段或别名、适用对象/方法/课题、条件要求、类型、目标单位、转换规则、依据、审核状态、版本。显示名称可以改变，稳定含义 ID 不跟着改。

规则匹配有多个候选时显示冲突，不按创建顺序取第一条；跨课题推广规则需明确复核，单课题的默认条件不扩散成全局事实。

### 7.2 三步而非一步

1. **语义对齐：** 判断两个字段是否描述同一指标。
2. **口径检查：** 核对对象、方法、条件、时间点、单位、归一化分母、统计量及重复类型。
3. **执行比较：** 按用户指定的任务计算或并列展示，给出排除和限制说明。

“条件不同”不必一律拒绝：若用户研究温度对结果的影响，温度就是比较变量；若用户要求同温度下性能排名，它就是必须一致的条件。可比性来自明确的问题，不来自全局“可以比较”标记。

### 7.3 换算和计算

- 已确认的确定性规则由程序执行，不让模型自由口算后覆盖数据。
- 保存原值、规范值、原单位、目标单位、公式/规则版本以及舍入说明；不虚增精度。
- 单位量纲相同也不一定可比，质量浓度和摩尔浓度还可能需要分子量，缺条件即停。
- 首版只开放明确支持的比较操作；差值、比值也要声明分母/基线与适用范围，不能从均值相近推出统计无差异。
- 异常值排除、平均或合并不是清洗默认行为，必须记录依据；派生结果引用输入快照和实际参数。

## 8. 搜索、范围与权限

### 8.1 三种互补读取方式

1. **文字检索：** 题名、正文片段、知识陈述、实际记录及人工标签；原文命中和确认知识命中分区。
2. **结构化筛选：** 课题、子问题、来源、知识性质、审核状态、指标、单位、方法、样品、时间、是否有未决缺口。
3. **关系展开：** 从结果找输入、从样品找状态与测量、从结论找支持/反例、从更正找受影响报告。

默认范围为当前课题，跨课题搜索由用户主动开启且只能访问有权限的对象。资料可复用不等于课题中的所有注释、实验数据及判断自动共享。

### 8.2 不把向量化作为首版前提

首版使用可重建的关键词/字段索引和真实关系查询。中文检索质量以真实查询样例验收；若规模和召回不足，再增加分词或向量召回。

向量索引若引入，也只提供候选：检索命中必须重新校验对象版本、权限与来源，向量相似不能生成“支持”关系；嵌入服务的外发同样需要授权。

### 8.3 正式与探索两种读取策略

- **正式证据使用：** 采用满足当前操作要求、已确认且未撤回的内容；缺乏出处的人工判断可以以判断身份呈现，不冒充证据。
- **资料探索：** 用户显式选择待审材料或原文用于“帮助理解/补查”，内容标记待审，不直接入正式计算或结论。

两种策略对人和 AI 使用同一套状态限制；不能只在界面隐藏待审内容，接口却默认全部返回。

## 9. 保存形式、版本与备份

### 9.1 运行时存储建议

现有默认数据路径由[服务启动配置](../../sciworkbench/server.ts#L79)决定，为 [sciworkbench/data/state.json](../../sciworkbench/data/state.json)，也可能通过 `LOCUS_DATA` 指向其他文件；本轮仅核查路径配置，未读取业务数据或密钥。

首版沿用现有 Store，增加知识专有元数据，如人工陈述、映射规则版本、来源锚点和构建记录；现有论文、表格、执行记录继续原位维护，不改为第二套知识实体库。

体积较大的不可变任务快照与导出包建议置于当前数据目录的专用子目录，主状态只登记 ID、hash、范围、格式版本和状态。此为拟议存储布局，不在本轮创建业务目录。

所有写入经过统一服务写入边界；先完整写入并验证快照，再将其标为 ready，失败构建不向用户或 AI 暴露半份导出，旧的 ready 版本仍可使用。

### 9.2 四种不同的版本

| 版本 | 解决的问题 |
| --- | --- |
| 对象内容版本 | 当时那张卡/那个表/那条判断是什么 |
| 映射规则版本 | 为什么当时把这两种表达对齐或换算 |
| 导出格式 / 投影器版本 | 机器如何解释字段，以及字段如何从原模块产生 |
| 任务快照 ID | 某次 wiki、比较或 AI 请求具体使用哪些输入 |

新生成的知识项版本保留完整的必要内容与固定引用。既有模块历史不完整时，从首次接入时建立可核验基线，不反推不存在的过去；索要未保存的历史内容必须返回“历史不可用”。

持续历史保障限定为已接入并纳管的对象：首次接入保存基线，之后每次相关内容更正都由统一写入边界先保全旧内容，再保存新内容及版本引用，历史保存失败则本次更正不能被当作完整成功。已有不可变完整修订可复用；只有字段差异且不能可靠重建的类型，增加该对象版本的只读完整历史副本；无业务 revision 的类型使用明确的知识层版本和内容 hash，不冒充业务原本就有版本。表格历史保留纳管表的列定义、行数据及来源对应关系，原件采用不可变资产版本，更换附件不覆盖旧资产；只保存 hash 而未保留内容不能算已归档。

这些历史副本不是第二个当前编辑入口，仅用于固定版本读取；未纳管对象及接入前缺失历史不在保障范围内，界面和接口必须显示覆盖边界。后续若绕过统一写入入口造成内容漂移，读取时校验 hash 并报告不一致，不能用最新内容伪装旧版本。

每次任务快照含实际所需值、范围、规则及证据摘录，不只列一串对象 ID；对应原件以 hash 和保留的资产版本固定。表格只有部分数据被选中时，保存选择规则、真实选中行及总/选中数量，不能静默用前 30 行代替整个数据集。

### 9.3 对外导出包的逻辑结构

以下名称是拟议包内条目，不是本轮已生成的文件：

```text
manifest.json             快照、范围、版本、文件hash、限制和排除说明
knowledge.json            陈述、关系、来源锚点、审核与unknowns
mapping-rules.json        本次实际使用的规则及版本
schemas/                  JSON结构及各CSV的数据字典
references.json           引用token到对象版本/证据位置的映射
wiki/                     索引、问题、主题、方法、比较、缺口与来源页
analysis-tables/           适合分析的CSV及类型/缺失值语义
source-excerpts/           经许可且经用户选择的必要片段
attachments/               仅在明确允许时附带的原件
```

- JSON 保存关系、状态、类型与缺口；CSV 一行代表约定观察单位，包含稳定记录引用，复杂元数据从 JSON 关联。
- Markdown 是人读视图，不承担唯一的数据规范；不同视图允许信息详略不同，但共同事实必须一致，省略明确说明。
- 提供给电子表格打开的 CSV 需防公式注入，机器分析 CSV 保留准确值并附类型说明，不能为了显示安全静默污染原数据；两种用途明确命名。
- 导出禁止包含 AI Key、认证头、个人本机绝对路径、未选聊天及无权限材料；论文许可和私密研究数据的发送授权是两项不同检查。
- 附件缺失或不允许附带时，保留题录、可公开定位和排除原因，不能生成假装可打开的链接。

### 9.4 快照包不等于全库备份

知识包只保存任务范围，不保证恢复全部业务记录；全库备份沿用并扩展现有备份路径以覆盖新增知识元数据和必要快照。搜索索引可以重建，无需作为权威内容备份；恢复必须先在隔离副本验证，不能覆盖用户现用数据。

## 10. 人类如何看：五种视图，共用同一批对象

### 10.1 可视化沉淀页面是明确交付，不只是附加视图

用户已明确最终需要一个可视化页面，展示已沉淀的数据与文献知识；因此本设计将“知识总览”作为明确页面交付，不能以审阅列表、导出按钮或一张关系图替代。页面具体导航位置尚待确认，建议放在既有“知识”入口，提供“总览 / 审阅 / wiki / 比较”的切换；原文审阅保留为生产知识的工作区，知识总览负责消费与复用已积累成果。

页面设计草图（仅设计说明，尚未实现）：

```text
┌ 课题 / 子问题    搜索    来源·知识性质·条件筛选    当前/快照 ┐
├ 研究问题与已沉淀主题 ─────────────────────────────────────┤
│ 左：问题/主题导航 │ 中：当前认识、适用条件、支持与限制      │
│                  │     文献证据 / 本地数据分层             │
│                  │     可展开比较表或图                    │
│                  │     尚不能回答的问题、上游更新提醒      │
├──────────────────┴───────────────────────────────────────┤
│ 选中知识 → 右侧证据抽屉：原文 / 条件来源 / 表格位置 / 修订  │
│ 当前范围 → 阅读wiki / 加入比较 / 选择AI上下文 / 导出快照    │
└──────────────────────────────────────────────────────────┘
```

显示规则：

- 默认显示已核对的知识与数据；假设、解释、作者报告和本地实测有明显标识，确认不等于事实化。未审材料进入独立待审入口，不混进“当前认识”。
- 按研究问题、主题、指标及条件组织，不按附件上传顺序堆文件；用户既可从问题读认识，也可从条件筛选回到数据。
- “当前认识”只能来自已确认的派生陈述或客观证据列表，没有确认的综合判断时显示“尚未形成综合判断”，不在页面加载时自由生成结论。
- 文献证据与本地研究并列且标明性质，方法来源可相同但不能因此合并为同一次实验。
- 选择一个主题同步过滤知识、数据、比较与局部关系；选择图表点或单元格打开同一引用的证据抽屉。
- 图中数值类型原样表达：不等式显示界限/箭头，定性“立即下沉”作为标签，不强制成数值零；没有重复和误差就不画虚构误差棒。
- 提示“当前筛选涵盖哪些文献、数据集和陈述”；文件数、卡数不叫独立证据数，不用总量代替知识质量。
- 空数据时显示尚缺哪个输入步骤；条件不兼容时保留条目与原因；原文缺失时仍可查看既存陈述及定位失败说明，不跳到近似来源冒充成功。

这是同一知识快照的交互视图，wiki 是叙述视图，JSON/CSV/API 是机器视图。三者使用相同知识项 ID、条件引用、来源 token 和状态策略；切换当前/旧快照后，所有子视图一起切换，不能图看旧版而抽屉读取最新版。

### 10.2 五种视图及其作用

| 视图 | 用户解决的问题 | 必须具备 |
| --- | --- | --- |
| 课题概览 | 我们已知道什么，还缺什么 | 子问题导航、已确认陈述、矛盾与缺口、更新提醒，不做无依据成熟度评分 |
| Markdown wiki | 系统地阅读方法与证据 | 主题/问题页、出处、版本、类型、确认状态、反例、未决问题 |
| 比较表 / 图 | 哪些可以比较，差在哪里 | 原值/规范值切换、条件列、排除原因、点选到证据；图不自动暗示统计显著性 |
| 局部关系图 | 这个结论来自哪里，改动影响谁 | 从当前对象展开一至两层，关系有类别，不默认展示全库毛线团 |
| 回查与修订面板 | 原文真是这样吗，什么时候变了 | 当前/引用版本对照、原句/单元格高亮、定位失败提示、变更原因 |

### 10.3 wiki 的页面结构

按课题建立以下页型，而不是按所有数据库表机械生成一页一实体：

- **课题首页：** 研究问题、资料范围、当前知识概况、重要缺口、快照版本。
- **子问题页：** 相关主张、支持证据、反例、适用条件、尚不能回答的部分。
- **主题页：** 某对象/机制/指标的已确认知识与术语映射。
- **方法页：** 文献方法、当前方案、实际执行差异与使用条件。
- **比较页：** 比较目的、规则、表格/图、限制及引用。
- **来源页：** 题录、附件、原文摘录、被引用位置。
- **缺口页：** 按影响分组的待补条件、待审材料和待验证事项。

页面块来自现有陈述、数据视图和关系，模板化组织是默认生成方式。可选 AI 综述作为额外草稿块持久化，须有自身来源与审核状态，再同时进入 JSON 和 wiki，不能临时在渲染时让 AI 改写已确认事实。

wiki 页面有“当前视图”和“已冻结版本”之别；当前页可显示新变化，导出历史版保持不变。导出的相对链接落到包内来源页/片段；回到正在运行的 LOCUS 可用引用 token 解析，不把个人本机路径嵌进可分享文档。

## 11. AI 如何接入：读取、发送、回流分别设计

### 11.1 内置 AI：不是直接读全库状态

内置方法推荐、下一步方向分析、范围对话统一调用知识读取服务：

```text
明确问题与范围
→ 检索候选并检查权限/审核
→ 用户查看核心、可选、排除内容
→ 固定知识快照
→ 按模型预算生成上下文包
→ 用户确认外发范围
→ 调用模型
→ 保存实际发送内容、快照引用和返回结果
→ 人工采纳需要回写的部分
```

同源表示相同对象在不同用途下具有一致含义，不要求给每个模型发送完全相同字节。上下文预算不足时可分页、缩小范围或生成有标记的摘要；记录 `complete/partial`、选中与省略数量、摘要生成版本，不把截断内容描述成完整输入。

原文是外部数据而不是系统指令，检索片段不能获得工具执行或任意发网权限。模型输出的引用必须解析到本次包内真实引用，不存在的 ID 标为无效；引用有效也仍不保证论断正确。

### 11.2 外部 AI：两条交付路径

**A. 文件导入，优先落地。** 用户预览并导出知识包，将 JSON/CSV/wiki 或其中选定部分交给支持文件的 AI 工具；LOCUS 无法保证每个工具支持 ZIP、完整读取所有文件或遵守引用约定，需用选定工具做实测。

**B. 受限只读接口，后续接入。** 外部客户端按被授予的课题/快照范围检索和分页读取；首个受支持接入可限本机客户端，跨网络访问待鉴权与部署方案完成，不能将现有全状态 API 直接公开。

拟议接口语义，路径仅为设计候选、尚未实现：

| 操作 | 必要输入 | 必要输出 |
| --- | --- | --- |
| `GET /api/knowledge/search` | 课题、查询、类型/审核筛选、游标 | ID、版本、匹配说明、来源、状态、分页信息 |
| `GET /api/knowledge/items/{id}` | 指定版本 | 固定内容、关系、unknowns；历史缺失明确报错 |
| `GET /api/knowledge/datasets/{id}/rows` | 快照、列/行范围、游标 | 类型明确的数据、记录引用、完整性说明 |
| `GET /api/knowledge/snapshots/{id}` | 授权快照 ID | manifest、内容目录及允许读取的范围 |
| `GET /api/knowledge/references/{token}` | 本次引用 token | 指定版本的证据或缺失/权限不足状态 |
| `POST /api/knowledge/snapshots` | 本地用户确认的范围及目的 | 构建任务/快照 ID，不代表已向外发送 |

接口的原则是：外部默认只读、显式鉴权、范围最小化、请求限量与分页、密钥不在查询 URL、只返回获准片段；导出权限与原件下载权限可不同。MCP 如后续确有客户端需求，可以是这些服务的适配层，不成为第二套知识逻辑。

系统内读取旧快照采用“当前权限约束历史内容”的策略：每次读取、下载或发送都复检快照授权与其来源内容的当前可访问范围，冻结内容不冻结访问权。某来源撤权后，不再提供包含该来源的整包；可为剩余获准内容创建新的裁剪快照，列出不可用项，原快照不被静默改写。已完成的 ready 仅表示构建完整，不代表永久获准访问；已由用户下载或发送给外部的副本无法靠服务端撤权收回。

### 11.3 外部输出如何回来

首版支持用户手动提交分析结果或粘贴带引用的建议，通过现有模块写入候选；自动读取外部工具对话不在范围内。

结构化回流可携带快照 ID、引用 token、实际方法/参数、结果文件和建议性质；系统检查引用存在与输入版本一致后，展示为候选结果。引用不一致、输入已更新或缺少计算过程时明确显示，不自动写成已验证结论。

“AI 建议 → 用户确认 → 新陈述/报告块”形成派生链，不把 AI 输出当作新的原始实验来源，也不让摘要反复检索后变成循环自证。

## 12. 真实而简单的案例：干燥处理、海水漂浮与后续萌发

### 12.1 来源与事实边界

来源是 Charles Darwin，《On the Origin of Species》（1859 第一版）第十一章，正文印刷页 359–360。已核对工作区存放的公有领域原文转录：影印文件页序 371 对应印刷页 359，页序 372 对应印刷页 360，二者不得混称同一页码。

本节仅用于本地设计讨论，不分发内部测试包、不建立产品默认样本、不读取用户运行时实验数据。这里是文献所报告的历史观察，不是 LOCUS 用户做过的实验；现成验收脚本和派生 CSV 不是原始证据，不能用它们的简写代替原文核查。

原文描述带成熟浆果的芦笋植株：未干燥状态漂浮 23 天，干燥后漂浮 85 天，种子随后萌发。关键原句为：

> an asparagus plant with ripe berries floated for 23 days, when dried it floated for 85 days, and the seeds afterwards germinated

“随后萌发”并没有给出萌发率；23/85 是报告的漂浮时长，不能自动认定为统一标准下的死亡时间或精确最长存活时间。盐度、温度、重复数及后续培养细节未在这里选定的段落中量化，不能声称本轮已经检索完整著作后确认全书未报告。

### 12.2 从一句原文保存成哪些知识

| 条目 | 内容 | 关联条件/阶段 | 证据与限制 |
| --- | --- | --- | --- |
| K1 | 带熟果芦笋植株报告漂浮 23 天 | 未干燥状态；海水漂浮 | 原文结果句 + 上文介质说明；不猜测样本数 |
| K2 | 同类材料干燥后报告漂浮 85 天 | 干燥后；海水漂浮 | 对应结果句；不冒充同一株的配对测量 |
| K3 | 干燥漂浮处理后的种子随后萌发 | K2 相关材料的后续阶段 | 结果为“观察到萌发”，不是“萌发率100%”，培养条件待补 |
| J1 | 在作者报告的芦笋例子中，干燥处理对应更长的漂浮时长 | 限于该例和文献口径 | 由 K1/K2 的比较 B1 派生，经人审核后保存；不是统计显著性或普遍因果结论 |
| J2 | 该例与漂浮后仍有萌发能力相容 | 限于该例的处理及后续观察 | 由 K2/K3 支持，经人审核后保存；不是对所有物种或真实海洋传播的证明 |
| L1 | 作者认为真实波浪暴露下的漂浮时长会更短 | 真实海况外推限制 | 印刷页360的作者判断，不是本地测量或已量化波浪效应 |

K1–K3 是原始文献陈述的提取，J1/J2 是我们据此形成的派生认识，L1 是另有原文依据的作者限制。页面、wiki 和 AI 都必须保留这三个层次。

### 12.3 新材料如何让认识真正积累

同一段还记载两组不同对象的例子：成熟榛果未干燥时“立即下沉”，干燥后漂浮 90 天并在种植后萌发；Helosciadium 成熟种子在两天内下沉（原句 sank in two days，不能未经语义核对写成精确最大漂浮2天），干燥后漂浮超过90天并随后萌发。

它们加入同一主题，但不因为相邻就合并平均：对象和观测口径不同，“立即”保持定性，“超过90天”保留下界，不能写成0与90参与普通均值。来自同一文献的多个对象也不是多篇独立研究。

下一页转述 Martens 的相似研究，提到实际海水、交替湿润与暴露空气、材料选择和未预先干燥等差别；暴露空气不等于已经干燥。它应先成为“达尔文转述的另一研究及条件差异”，不能直接当作我们已读取并核验的一手研究，也不能因结果不同就标“反证”。

由此主题页可逐步形成三层内容：

1. **已知的条件化认识：** 这些被报告的例子中，干燥处理与较长漂浮时长相伴，部分材料之后仍萌发。
2. **不能据此推出的结论：** 所有物种都如此、干燥提高萌发率、真实海洋一定达到同样时长，或已经具有统计显著因果证据。
3. **可以复用到下一研究的要点：** 分开记录漂浮与后续萌发阶段、明确是否预干燥、区分受保护实验条件和波浪暴露、记录实际对象与独立重复；这些是基于缺口形成的方法建议，需用户决定是否纳入方案，不伪装成原文实验参数。

若用户后来真正开展实验，其方案与测量建立新的本地来源链，并链接这个知识主题，不覆盖历史陈述，也不自动制造“达尔文原实验执行记录”。本轮没有这样的本地实验，不能编造数值填满流程。

### 12.4 可视化页面与 wiki 应如何呈现

**主题标题：** 干燥处理是否影响漂浮，以及漂浮后还能否萌发？

- 顶部为有依据的当前认识及“限于文献所述例子”标记。
- 中部比较表列出对象、预处理、报告漂浮时长、后续萌发及来源；未核对跨物种可比性之前只作描述性并列。
- 芦笋 23/85 可用两点/条形显示并注明文献报告；榛果“立即下沉”使用文本标签，Helosciadium 的 >90 使用下界标识，不画成精确90。
- 右侧显示盐度、温度、重复与萌发条件等选定材料缺口，以及作者对波浪的限制判断。
- 点击 85 天，展开 K2 → 干燥漂浮上下文 → 原文结果句/方法片段，定位到印刷页359；点击“随后萌发”进入 K3 的后续阶段，而不是把萌发混成海水中的行为。
- wiki 使用同样的认识、比较和限制形成连贯文字；AI 接口返回相同的 K、C、E、J、L 固定引用，能够回答“依据是什么”和“不能推出什么”，而非只返回一个数字。

### 12.5 为什么这是沉淀，而不是文件柜或字段柜

文件柜只能找到达尔文原文；字段柜最多返回“芦笋、23、85、萌发”。这里留下的是“原文观察—适用条件—比较—有限认识—外推限制—可复用方法问题”的链条。

用户下一次研究海流传播时，不需要重新从零提取这几个句子的含义；可直接复用已核对的知识，看到证据、边界和待补条件，再把新研究接到同一主题上。是否沉淀的验收是：换一个阅读者或 AI，仍能正确回答有什么根据、适用于哪里、缺什么、新材料会修订哪个认识，而不是卡片数量变多。

### 13.1 文献入库链必须调整，保留骨架而不是推倒重写

需要改变的是输出契约、条件绑定、来源定位、去重与人审能力，不是再添一个独立“知识入库”按钮。

| 函数/位置 | 当前代码事实 | 设计调整 |

## 14. 执行方案与阶段出口

### P0：真实样例与边界确认

**输入：** 一个课题的脱敏题录/资料导出、现有 wiki 样式或理想目录、两种写法的指标、一个条件缺失反例、一个表格与执行记录、一次期望 AI 请求。

**动作：** 画清对象归属、人工操作、来源许可；确定首批格式、比较任务与不自动判断的事项。

**产物：** 样例清单、预期结果、最小词表、人工操作矩阵与验收用例。

**出口：** 用户确认“这个知识库能回答哪些问题、不能回答哪些问题”，不以数据库结构漂亮作为验收。

### P1：只读贯通与版本基线

**依赖：** P0。

**动作：** 为各现有板块建立最薄的统一读取适配，提供课题范围清单；补齐第一条垂直链的固定版本解析与来源锚点，登记旧历史不可用情况。

**产物：** 一个课题的机器可读清单及版本/来源检查结果；原模块不重复录入。

**出口：** 从选定陈述或表格行能够回到确定版本；旧引用不静默指向最新值。

### P2：分析项、映射与比较

**依赖：** P1。

**动作：** 按 §13.1 调整文献提取/条件绑定/去重/人审契约，完成字段级类型/单位、规则版本和三类可比性判定；保留原值，执行有限的确定性计算。

**产物：** 一个“原文→观察项→条件→来源→审核”的真实案例，一组正例、一组拒绝误比反例与规范化数据集。

**出口：** 两个写法能正确对齐；同名异义、缺单位或不满足任务条件时不能偷偷计算。

### P3：同源 wiki 与导出包

**依赖：** P1、P2。

**动作：** 从统一快照生成 JSON/CSV/Markdown，实现 §10.1 的知识总览可视化页面，以及课题/子问题/比较/来源页和回查面板；检查包内链接和许可排除。

**产物：** 展示已沉淀知识与数据的可视化页面、一份可离线阅读的 wiki、一份机器可读包和可回查的比较结果。

**出口：** 实际在浏览器验证主题/条件筛选→查看认识与比较→点击数据回查→阅读同源wiki的路径；视图共享事实一致；更新后生成新版，旧版不变；空数据、缺来源、不兼容条件和旧快照不会被美化为已完成或完整证据。格式失败不生成假完成包。

### P4：统一 AI 上下文与选定工具导入

**依赖：** P3。

**动作：** 内置 AI 改用同一读取契约，记录实际发送内容；选一个用户真实使用的外部 AI 工具做文件导入验证；结果回流仍经用户确认。

**产物：** 内外 AI 使用同一快照的可核查示例、有效/无效引用测试。

**出口：** 不泄漏未选材料，无法处理的文件/长度限制如实说明，模型回答能回到证据。

### P5：其余板块完整接入

**依赖：** P1 的适配盘点与 P3 的完整读取/展示契约；可与 P4 的外部工具验证独立安排。

**动作：** 按“方案与模板 → 执行与样品状态 → 测量和分析结果 → 报告与采纳对话”逐批补齐详细适配、持续版本保全、来源解析、确认状态和页面联动，复用已有业务字段，不新造一套科研工作流。

**产物：** 每类对象的接入清单和单条贯穿样例，方法页、实际执行差异、样品到结果关系及报告/采纳对话的派生链。

**出口：** 信息来源矩阵逐行验收：明确哪些字段已可读、哪些必须人工补充、哪些尚不支持；每类至少验证一次原模块更正后的新旧版本回查，以及其进入 wiki/AI 时的性质不变，特别验证计划不冒充实际、聊天不自动成为证据。

### P6：受限外部读取接口与扩展视图

**依赖：** P1 的版本读取、P3 的快照契约；可先针对首批已接入类型联调，全模块接口交付依赖 P5，外部开放还依赖鉴权与部署设计。

**动作：** 实现分页接口、授权范围、过期处理及实际客户端联调；按需求补充局部关系图、图表、方法页、向量召回或 MCP 适配。

**产物：** 一个受支持外部客户端的端到端读取结果及越权/历史版本测试。

**出口：** 外部调用不必获取整库，不改变业务数据，未授权内容不可读取。

### 首个可交付闭环与完整目标的区别

首个闭环覆盖“一课题、一问题、文献证据 + 本地表格、少数映射、wiki、比较和文件交 AI”，并在数据模型中保留方案/执行/报告等关系；P1 同时盘点其他板块，不能对未接入的详细内容声称已全覆盖。

完整目标再贯通方法/执行/样品/分析/报告及采纳后的对话，提供专用外部接口与相应视图。自动统计检验、跨领域本体、自动全库清洗、多用户平台重建不作为知识库闭环的前置条件；已有方法推荐功能不删除，只调整其读取来源。

各阶段宜形成独立、可验收的变更，不预估未经样例验证的工期，不因上一阶段通过就自动批准后续实施。

## 15. 验收清单

| 类别 | 必须验证的情形 |
| --- | --- |
| 非重复录入 | 在原模块保存或更正后，相关知识可见；无需重复填写同一数值 |
| 同源 | 同一快照的 JSON/CSV/wiki 共同字段一致，缺口和排除不因视图不同而消失 |
| 原始表达 | 规范化后仍能读到原字段、原值、原单位、原始片段及变换依据 |
| 科学语义 | 计划不等于实际，报告不等于新证据，人工确认不等于证明假设 |
| 正向比较 | 已知同义字段、兼容口径与正确换算产生预期结果 |
| 负向比较 | 同名异义、条件不足、统计口径不同、单位歧义不能自动合并 |
| 缺失值 | 空、0、未测、低于检出限、冲突分别保留；影响计算时明确阻断 |
| 独立性 | 同源拆卡、综述转引、报告/AI 再述不增加独立证据计数 |
| 版本 | 修改原数据或映射后，新旧快照各自可解释；未保存历史明确不可用 |
| 定位 | 能回到引文/固定表格单元格；多义、缺失、权限不足分别提示 |
| 人工操作 | 导入不自动采纳，聊天不自动成知识；已确认业务事实不重复审核 |
| 后台一致性 | 提取失败、取消、重试、期间人工修改均不覆盖已保存工作，不产出半包 |
| 检索 | 按真实问题找到目标材料并标来源/状态；无权限内容不进入结果或片段 |
| AI 输入 | 实际发送清单可查，截断/摘要明确，未授权原件与密钥不外发 |
| AI 输出 | 引用 token 可解析；捏造引用无效；用户确认前不写成正式事实 |
| 恢复 | 快照/索引损坏显式失败，备份隔离恢复可验证；不静默生成空知识库 |
| 浏览器体验 | 审阅、wiki、比较、回查黄金路径及空数据/长表/缺来源/窄屏实测 |

本轮仅设计与代码核查，以上验收尚未执行；不将已有测试数量作为新功能已通过的证明。

## 16. 讨论时优先拍板的事项

1. **知识入口定位：** 可视化沉淀页面已由用户明确要求；待确认的是“总览/审阅/wiki/比较”的具体导航，而不是是否做页面。
2. **真实样例：** §12 已用真实达尔文文献解释沉淀机制，仅为本地设计案例，不替代用户课题或授权公开内部材料；仍须确定正式首个课题、字段及比较，用户数据未提供前不冻结领域词表。
3. **wiki 编辑：** 建议页面可发起修改，但最终编辑的是内部对象/人工说明，不双向同步任意 Markdown。
4. **首批外部 AI：** 先支持哪个真实工具、文件导入还是本机读取客户端；未经验证不承诺兼容所有工具。
5. **外发范围：** 哪些材料允许摘录、允许带原件、只允许本地使用；许可缺失不由 AI 自行补齐。

其余工程默认建议已经给出，可以继续逐节修订；这些待定项不妨碍完整阅读本稿，也不构成已批准实施的事实。
