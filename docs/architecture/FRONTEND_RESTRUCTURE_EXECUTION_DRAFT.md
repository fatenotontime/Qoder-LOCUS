# LOCUS 前端重构工作指南 · 草案 v0.1

> 面向：前端设计与实现 Agent / 前端开发者。目标：把已有功能组织成真正可工作的页面，而不是给原来的多栏表单换皮。
> 状态：供用户审阅的第一版；本文本身不是开工、提交或部署授权。两项布局建议和容器外形尚未由用户定稿。
> 提交授权说明（S04-T14）：本方案及相关记录的本次提交，由用户在特殊情况下明确允许，用于交由前端工作者查收。此授权不代表方案全部定稿，不扩大为代码实施、部署或解除 E6-B 暂停，也不构成今后自动提交的通用授权。
> 本稿只定义前端体验与协作边界。知识语义、权限、固定版本与验收仍以[知识库执行合同](KNOWLEDGE_BASE_EXECUTION_SPEC.md)，尤其 E6 为准。本文不修改该合同，不解除 E6-B 停点。

## 1. 给前端的总任务

你不是在重新开发七套业务系统，也不是把所有功能重新排进七个相同的面板。你的任务是让研究者每次进入页面，都知道：**我在哪里、这里有什么、现在能做什么、完成后去哪里。**

LOCUS 应像一张整理好的研究桌：资料管理时能快速找东西，阅读时能安静看原文，实验时能宽敞记录，审阅时能同时核对证据，积累后能直观看见自己的研究资产。书卷、宣纸、光卷和迹芽是这张桌子的性格，不应成为操作障碍。

本次设计的核心不是“减少栏数”，而是以下三个变化：

1. **从功能全部摊开，改为按当前任务展开。** 管理、阅读、编辑、审阅分别有自己的页面状态，不把新建表单、对象目录、当前详情、辅助工具永久并排。
2. **从所有区域同样抢眼，改为每页只有一个视觉中心。** 文献看正文，方案看方案图，记录看表，知识看沉淀，对话看消息。辅助信息需要时再展开。
3. **从导航只是换内容，改为完整的进入与返回。** 点开对象、查来源、返回列表，应保留筛选、位置、选择和未保存内容保护。

### 1.1 已明确、建议采用、仍待定

| 层级 | 本稿采用的口径 |
| --- | --- |
| 用户已明确 | 按页面工作逻辑重构；课题目录不常驻；文献管理/阅读分开；知识大容器为最终主页面核心；方案管理/详情分开；记录总览/子页；对话管理/聊天分开；分析暂缓；迹芽参与知识积累体验 |
| 草案建议，待用户确认 | 当前课题名与“切换”常驻顶栏；文献阅读时从右侧拉出文献库，不把整个文献模块永久固定到右栏 |
| 视觉待定 | 大容器最终外形。石榴剖面只是候选，不是已确认品牌；先画灰阶轮廓与元素关系，不自行制作成正式品牌素材 |
| 前端可自行细化 | 在本稿范围内的栅格、留白、组件拆分、交互细节与内容断点；需要展示理由及窄屏效果，不必把每个像素交给用户决定 |
| 不能自行改变 | 审核语义、来源权限、固定版本、真实业务状态、分析业务流程；不能为迁就页面补造指标或新写入接口 |

### 1.2 对开发者意见的吸收与修正

“按页声明布局”“保留明显课题切换”“创建表单离开详情顶部”“分批重构”“迹芽不替代高效审阅”均采纳为草案原则。

“先做容器骨架”是合理的实施顺序，**不是永久取消容器主页面**。截至本稿核对的仓库基线，E0–E5 已有实施记录，E6-A 容器与流水线数据接线也已完成；E6-B 页面集成仍等待前端交付与用户确认。因此不应再以“整个数据模型尚未开始”为前提拖后设计，也不能把接口已存在等同于页面已验收。

## 2. 先建立页面层级，再安排组件

一级导航仍保留七个入口，书脊负责“切换工作领域”，不要同时塞进所有课题目录与对象目录。页内导航负责管理、详情等任务切换。

```text
顶栏：品牌 | 当前课题名称 [切换] | 全局状态、主题与设置
书脊：课题 / 文献 / 知识 / 方案 / 记录 / 分析 / 对话

课题 → 当前课题总览 → 子问题详情
     ↘ 顶栏切换器 → 课题目录 / 新建课题
文献 → 文献管理 → 文献阅读 → 来源定位
              ↘ 导入流程
知识 → 积累总览 → 元素详情 → 来源定位
              ↘ 继续积累 → 扫描 / 待审队列 / 分项审阅
              ↘ 知识目录（wiki） / 比较 / 快照
方案 → 方案管理 → 单方案详情 → 编辑当前方案
记录 → 记录总览 → 执行详情 / 数据表详情 / 样品详情
分析 → 保持现有业务布局与流程
对话 → 会话管理 → 标准聊天 → 范围查看 / 来源回查 / 采纳确认
              ↘ 新建会话与范围选择
```

这些是用户可感知的页面状态，不强制采用某个 URL 库或框架。实现时应给出实际导航状态、返回目标和对象标识；不能只改标题或用隐藏面板假装已拆页。

### 2.1 壳层只提供布局能力，不替页面决定布局

| 布局能力 | 用途 | 默认收起的部分 |
| --- | --- | --- |
| 单主体 | 总览、管理列表、文献阅读、聊天 | 对象目录、属性详情、辅助工具 |
| 主体＋辅助区 | 方案详情、样品详情、选中知识后的详情 | 无选中对象时不保留空白侧栏 |
| 核对工作区 | 知识分项审阅等需要同时对照的任务 | 窄屏先收队列，不先压缩原文与核对表单 |
| 宽表/画布 | 数据表、方案图 | 长文本属性与录入表单移入按需面板 |

三栏或四栏不是禁用项，但每一栏必须回答“为什么用户需要同时看它”。如果答案只是“以前就在这里”，不作为保留理由。分析页暂不套新内容布局，只保证壳层改动不破坏它。

### 2.2 全局课题切换

草案采用顶栏“当前课题名＋切换”。默认只显示当前课题，不永久展开全部课题列表。切换器打开后可查找和选择课题；“新建课题”留在切换器或课题管理中。

切换前经过未保存保护；切换后更新范围标识和本课题内容。上个课题的详情不能继续冒充当前课题对象；无对应对象时回到该模块管理/总览态。没有课题时直说“尚未选择课题”，不伪造默认课题。宽度不足可省略名称，但“切换”不能消失，完整名称须可查看。

## 3. 视觉与交互语言

### 3.1 让内容成为主角

延续已有宣纸/光卷双主题、书脊导航和品牌资产，不重新发明一套无关的后台管理模板。宣纸主题强调温和层次与阅读感；光卷主题强调清晰线条与状态辨识。两套主题保持同样的信息结构和操作位置，而不是一套完整、一套简单反色。

具体设计基线：

- 页面标题、范围说明、主操作组成紧凑页头，不使用巨大欢迎横幅占掉工作区。每个页面状态通常只有一个突出主操作，其余用次级按钮或更多菜单。
- 标题、正文、辅助标签至少有清晰层次。普通正文建议 14–16px、行高约 1.6；密集表格可更紧，但不靠全页缩小字体容纳内容。复用现有间距变量，区块间留白大于区块内部间距。
- 不给每段内容都加一层卡片边框；列表用行和分隔，详情用章节，画布用留白。阴影、纹理和光效不能盖过文字或网格。
- 状态同时用文字和视觉标识表达。选中、焦点、成功、警告、错误不可混成同一种强调色；颜色不代表知识可信度高低。
- 管理页重扫描效率，详情页重连续阅读，审阅页重并列核对。三者不应有同一套信息密度。

以下宽度是首版排版起点，不是最终尺寸合同：阅读正文约 720–960px；按需详情区约 320–400px；审阅队列约 220–280px。有效宽度不足时切换布局，不把所有区域一起挤到不可读。

### 3.2 创建、编辑、查看分工

**管理页创建，详情页查看，进入编辑态才编辑。** 简短创建可用对话框，中等表单用抽屉，复杂导入用独立流程；不要把长表单硬塞进小弹窗。

详情页可有“编辑”“管理附件”等明确入口，但不能常驻另建一个对象的完整表单。保存操作贴近当前编辑内容，保存中防重复提交，失败保留输入并就地给出原因。不得借页面重排改成未经设计的自动保存。

### 3.3 抽屉不能成为新的杂物间

右侧文献库、知识详情、属性编辑是不同用途，分别定义标题、范围与关闭结果。默认只打开一个主要辅助面板；从详情查来源时进入阅读/核对状态并保留返回点，不层叠三四个抽屉。

模态面板管理焦点并阻止背景误操作；非模态辅助区允许继续操作主体。关闭后焦点回到触发入口。Escape 不能绕过未保存保护。

## 4. 各页的前端设计任务

### 4.1 课题：打开后知道这项研究在做什么

**第一眼：当前课题名称、研究目标与正在推进的子问题。** 不再让所有课题目录和创建表单占主体。

主体上部展示目标摘要；中部以子问题作为可进入的工作单元；下部给出相关材料与最近进展的真实入口。待办与下一步作为辅助，不做另一套抢眼仪表盘。没有可靠进度定义时，不画“研究完成 68%”等百分比。

```text
课题名称                         [编辑]
研究目标 / 当前范围

子问题 A        子问题 B        子问题 C
简述与真实状态   简述与真实状态   简述与真实状态

相关材料与最近进展              下一步 / 待办
```

点击子问题查看它的内容与相关对象，返回时恢复总览位置。新增子问题留一个按钮，点击后才展开表单。空课题先引导写研究目标或添加子问题，不同时抛出十种导入选项。

验收画面：有数据时首屏是“当前课题”，而不是“课题创建器”；用户无需找隐藏图标就能换课题。

### 4.2 文献：管理时找得到，阅读时看得进去

**管理页**默认呈现可扫描的文献列表：题名为主，作者/年份、附件情况和相关状态为辅。顶部放搜索、少量筛选与“导入”；条目内给“阅读”“附件”等操作。批量管理只在选择条目后出现，不默认铺满工具栏。

导入作为独立状态：选材料 → 核对条目与附件 → 提交 → 结果。只保留现有支持的导入能力；缺失能力列明，不为凑步骤承诺未实现功能。导入成功回到新条目位置，可直接阅读；失败保留已填内容和明确错误。

**阅读页**以原文为中心，默认不显示导入表单、全库列表和大块元数据。

```text
[返回文献] 文献题名             [附件] [文献库] [更多]
附件名 / 当前查看版本 / 定位提示

                  原文阅读区域
                  正文、原图或已有阅读器

点击“文献库” → 右侧打开检索/切换列表；默认关闭
```

本稿将“文献放右边”解释为**阅读时右侧拉出库**，不是把正文或整个文献模块永久挪到右栏。打开库后正文仍须有可读宽度；窄屏改成覆盖式选择页，选中文献后关闭。

从知识项查来源时，进入的是指定附件、指定版本、指定位置，而不是文献首页；保留“返回审阅/返回知识”入口。定位不确定时展示候选或无法定位说明，不能高亮第一处冒充唯一证据。元数据编辑与附件管理按需进入，不挤占日常阅读。

验收画面：打开一篇文献时，正文是首屏面积最大的区域；在库中换篇后，返回管理页仍能找回原筛选与列表位置。

### 4.3 知识总览：让积累可见、可找、可回查

**第一眼不是待审表单，而是当前课题已经沉淀的知识与数据。** 大容器是最终主视觉与导航载体，不是背景插画。

```text
知识积累   当前课题 / 当前库     [继续积累]
知识项数 · 数据集数 · 待审数     [筛选] [列表]

             大容器：按主题 / 子问题组织
             可选知识元素、数据集聚合入口
             未分主题区域，不丢弃未分类项

图例与范围说明                  [知识目录] [比较] [快照]
```

容器内部采用“有含义的元素”，而不是随机粒子：

- 一条知识项有一个可寻址元素；点击或键盘选中后呈现摘要、性质、数值/单位、条件和来源。一个知识项关联多个主题时，不因此虚增总项数；交叉归属用关联提示表达。
- 条件和来源是知识的附属展开信息，不把它们拆成无关系的装饰籽。数据集作为聚合元素进入，展开后才到表；不把每个单元格都画成知识项。
- 首版优先用稳定轮廓和有限类别标识。内容类别帮助辨认，审核/待补状态用独立标记。不同单位的数值不得直接决定大小，位置和大小不得暗示未经定义的科学重要性。
- 默认正式积累与待审候选分开；保留明确文字说明。人工确认的假设仍显示为假设，不因“成熟果实”动画被画成事实。
- 元素太多时允许按组聚合、分页或逐层展开，但显示“匹配多少、当前加载多少、已知总量多少”。聚合图形是入口，不冒充单条知识，也不声称屏幕已逐个显示全库。
- 选中后元素与详情联动；搜索结果可定位，过滤后仍显示当前过滤条件；容器和同源列表保持相同范围、选择与返回点。不得提供两个统计口径不同的“库”。

容器视图提供概览与空间记忆，列表提供精确检索和高密度工作，二者都是正式入口。不要强迫用户逐个点击细小图形才能找知识。

**骨架期**：可以展示空容器、分类区和清晰的“尚未接入”状态；设计样例仅用于独立设计稿且标注“合成示意”，不能混入真实库计数。接口不可用不等于库为空，不能用 0 伪装错误。

**E6 集成后**：元素、计数、范围、详情与来源均由真实数据驱动，当前/快照切换可用；仅有总览数字、空容器或静态图不能签署最终完成。

#### 从总览深入：知识目录、比较与快照

这些不是挂在角落的占位按钮，而是容器之外的真实工作目的地：

**知识目录（wiki）**：以连续阅读为主体，显示当前范围及“认识、文献知识、研究数据、条件、限制/缺口”等目录入口；宽屏可有章节目录，窄屏可收起。正文中的来源标记能回查，选中知识能返回总览对应项。wiki 是只读派生表达，修改内容通过原知识编辑入口，不另造第二套正文编辑器。

**比较页**：从总览选择知识项或从数据集选择单元格进入；上部明确两个操作数及各自条件/单位，下部呈现结果、判断依据与不能计算的原因。允许查看并列材料，但“仅并列”不伪装成可计算。缺条件或映射时就地显示缺口，不画出默认零值。返回总览保留选中项；旧比较历史若只能展示，标明其历史展示身份，不接回未整改的旧写入链路。业务适配由对应负责人按合同收口，前端不自行降门槛。

**快照与导出**：总览的“快照”进入快照选择与管理状态；“冻结”放在当前范围预览之后，先展示将固定的内容和范围，再提交。冻结成功才进入该快照，失败保持当前视图与选择。快照阅读页常驻“历史快照”标识与“返回当前”入口，不显示可修改历史内容的按钮。导出在选定快照的操作区选择现有支持的 JSON、CSV、wiki 或知识包，说明内容范围与排除项；权限拒绝、生成失败或下载失败均有可读错误，不假报下载成功。历史快照也继续显示动态权限/有效性警告。

这三处沿用总览的课题/范围信息，并各有明确返回入口；前端骨架可先交布局，但 E6-B 必须接成真实可操作页面，不能用页面已存在代替冻结、导出和回查验证。

### 4.4 继续积累与审阅：用迹芽讲过程，用工作区完成判断

“继续积累”进入单独工作流程：选文献与附件、写提取目的、确认范围、开始扫描。发起扫描是显式操作，页面进入或动画播放不能自动调用模型。

流水线可采用“材料进入 → 候选出现 → 待审 → 人工确认后归入”的叙事。顶部用轻量迹芽状态带表达阶段；下方有可搜索/筛选/进入的真实任务与待审列表。失败、暂停、待补不是生长阶段，必须直接说明原因和可执行操作。

审阅采用任务型多栏，而不是装饰型流水线：

```text
[返回积累] 本次任务 / 处理状态              [暂停等真实可用操作]
迹芽阶段提示：扫描 / 待审 / 已归入（保留文字）

待审队列            原文与定位                 当前知识核对
简述 / 状态          附件 / 版本 / 引文          内容、条件、性质
筛选 / 当前选择      可持续阅读                 未知项与阻断原因
                                               [待补] [排除] [确认]
```

充分宽屏时三工作区并列；中等宽度先收队列，保留原文与核对两区；窄屏用“原文/核对”切换与明确队列入口，不把三栏缩成细条。

重点行为：

- 点列表、容器元素或普通按钮都能进入详情，迹芽不是唯一入口。确认按钮不能用无文字的果实图标替代。
- 先看需要判断的陈述，再看对应条件与证据；长字段分节展开，阻断确认的问题必须可见。旧版、当前版、改绑是明确动作，不用重新打开卡片偷偷切换版本。
- 确认成功后再更新队列与正式计数。可提供“下一条”，但不能自动抢走焦点、抹掉待核对的结果或将整篇文献默认为已确认。
- 扫描进度、已保存候选数和人工确认数分别表达；不可把“扫描完成”等同于“全部归入”。动画仅响应已确认的服务端状态，刷新或重放不能再次入库或重复庆祝。
- `kzJob` 是现有前端状态入口之一，不是唯一持久事实。任务恢复、离开后返回与计数以实际 run/pipeline 接口为准；适配器核实真实字段，不能只观察一个内存变量画动画。
- 减少动态效果开启时保留相同信息与全部操作；用户关闭动画后仍能完成整条审阅链。

### 4.5 方案：先选方案，再进入一张干净的实验图

**管理页**展示方案列表与检索，突出名称、目的和可解释状态，提供“新建”“导入”等现有入口；模板与导入流程不常驻每个方案详情顶部。

**详情页**展示当前方案标题、查看版本和实验图/步骤主体。属性、来源、历史按需展开；点击图节点就地看步骤详情。编辑当前方案有明确编辑态与保存/取消，不能把“查看历史版”做成可直接编辑旧版。

```text
[返回方案] 当前方案名称 / 版本        [编辑] [更多]

                 实验图 / 步骤主画布
                 选中节点 → 步骤详情

需要时展开：方案属性 / 来源 / 版本历史
```

画布可平移、缩放或展开时，应有可发现的重置视图入口；没有现成能力时列为单独交互增量，不偷换成静态示意。已有从方案到执行的入口保留语义；不将浏览方案与创建执行混成同一按钮。

验收画面：进入某方案，第一眼看见的是该方案，而非“再创建一个方案”的表单。

### 4.6 记录：把实验记录从狭窄附栏搬回工作区

**总览页**帮助用户找到一次执行、一张数据表或一个样品。用“执行 / 数据 / 样品”页签或清楚分区组织，不强制把三类都塞成等高卡片墙。只展示已有业务能支持的真实摘要；新的跨执行聚合若需要后端能力，单列缺口，不在浏览器里猜关联。

**执行详情**：页头是本次执行与关联方案；主体是步骤记录和计划/实际对照；样品、数据、事件历史进入子页或辅助区。准备阶段仍清楚标记为准备，不因统一详情布局跳过确认流程。

**数据表详情**：表格占最大宽度，筛选和列工具靠近表头；录入、修订或导入按需打开。允许表格本身横向滚动，不允许整张页面因为宽表横向溢出。选中单元格后的来源/说明靠近选择区，不把表格缩到第三栏。

**样品详情**：名称与稳定编号、状态、分样关系、已有测量清楚分组；新增测量/分样为显式动作。名称恰好等于编号时不重复打印两遍。

验收画面：执行、数据表、样品都能独立展开并返回原总览；填表时不会因为刷新任务状态丢输入。

### 4.7 对话：先管理研究会话，再进入真正的聊天

**管理页**展示会话列表、标题、所属课题/子问题、最近活动及范围摘要。新建会话时填写目的并选择范围；可复用现有上下文地图表达核心与可选内容，但不假定分析地图的数据模型已经可直接用于对话。只复用合适的展示与选择能力，接口不兼容时明确列出接线任务。

**聊天页**以消息流为中心，输入区固定在聊天工作区底部。长历史只滚消息区，输入区不随历史滚走，也不遮住最后一条消息。

```text
[返回会话] 会话标题              范围摘要 [查看范围]

                  消息流
                  引用可回查
                  建议有明确采纳入口

                 输入内容……         [发送]
```

范围摘要常可见，详细地图/来源按需展开。发送时仍按既有规则冻结本次输入；调整后续范围不能改写已发送消息的快照。等待、流式生成、取消、失败重试沿用真实任务状态。用户上翻历史时不强制滚到底部，而显示新内容提示。

AI回答与正式采纳分开：看到建议不等于应用建议；“采纳”须展示目标和变更供确认。资料选择界面不等于已经授权外发，已有权限与确认边界保留。

### 4.8 分析：本轮不重新设计

保留现有分析流程、上下文地图、推荐、快照与结果布局。全局壳层、主题、滚动或导航发生变化时必须做回归，不因“暂缓”漏验；但不顺手将分析改成新的聊天式工作流。

## 5. 跨页面必须一致的体验

### 5.1 返回、滚动、选择与未保存内容

每个管理→详情跳转记录返回来源；至少包含课题、子页、筛选、列表位置和选择项。查原文后能回到那条知识，查看样品后能回到那次执行，而不只是回到模块首页。

状态记忆按“课题＋模块＋子页＋对象”区分，不能仅按旧的左/中/右面板编号恢复。失效对象显示说明并回到可用入口；不恢复已不存在的元素。路由形式由前端方案说明，但页面内返回和浏览器返回不能各走一套未经保护的离开逻辑。

新页面不得绕过现有 dirty 保护：切课题、切页、换对象、关闭编辑抽屉、浏览器返回都要覆盖。保存失败保留输入；放弃前确认；关闭提示继续留在原编辑位置。无需本轮发明自动草稿保存，但不能静默丢草稿。后台完成只更新安全的状态区，不能重建编辑DOM清空表单。

### 5.2 加载、空白、失败必须区分

| 状态 | 呈现原则 |
| --- | --- |
| 首次加载 | 按实际内容结构显示占位，标明加载中，不展示虚假统计 |
| 真正为空 | 一句解释＋一个首要下一步；无文献、无积累、无执行分别引导 |
| 筛选无结果 | 保留筛选，提供清除条件，不让用户误以为全库为空 |
| 后台处理中 | 就地显示真实阶段，不遮住全部页面；只有真实支持时才给暂停/取消 |
| 部分成功 | 分开显示成功与失败部分，仅重试可重试项，不要求全部重来 |
| 读取失败 | 显示失败与重试；保留旧内容时标明尚未更新，不能把旧值冒充最新 |
| 权限/历史不可用 | 明确原因和可做的下一步，绝不自动改用最新版或其他来源 |
| 版本冲突 | 保留用户输入，提示重新核对差异；不自动覆盖、不自动重绑 |

普通文案说人话。导航/按钮优先四字以内，但错误解释不为凑字数牺牲含义。可见时间、状态、版本复用 `public/lib/format.js`；不裸露 ISO 时间、英文枚举或无解释版本串。技术标识可放可复制的详情，不占主要标题。

### 5.3 窄屏、键盘与动画

建议用 1440、1024、768、390 CSS 像素宽作为布局检查点，并结合 200% 缩放检查可操作性；这是排版验证点，不是要求四套固定样式。

- 宽屏放大内容，不无限拉长阅读行；中屏先折叠辅助区；窄屏保留当前课题与模块识别，再切换主体/辅助页。不能仅隐藏功能而不给替代入口。
- 每页指定一个主滚动区；只有审阅并列阅读或宽表等必要场景允许独立滚动，避免“页面、卡片、卡片内列表”三层套滚动。
- 所有关键动作可用键盘，焦点可见，选中不只靠颜色，触控目标有足够面积。小图形可以扩大透明点击区域，但不能互相重叠导致误选。
- 容器提供等价列表；自定义键盘导航需提示使用方法，不让用户 Tab 穿过上千个装饰节点。审阅快捷键不能在文本输入时触发确认或删除。
- 操作反馈通常短而轻；主题过渡保留品牌感但不丢焦点、不清选择、不吞操作。`prefers-reduced-motion` 下取消非必要位移/生长动画，静态状态仍完整。
- 迹芽用于扫描入口、任务反馈和知识归入等合适节点，不替换保存、删除、确认等所有按钮；素材缺失时用诚实的普通按钮，不用随意表情拼成品牌。

## 6. 实施顺序与阶段交付

以下是草案获准后的实施路线，不是本轮开始执行的命令。每阶段只改对应页面及必要公共能力，不一次性替换七页。

| 阶段 | 产物 | 完成依据 |
| --- | --- | --- |
| F0 体验方案 | 导航树、页面布局表、关键低保真框架；现有功能→新入口清单；标出两项待确认建议与容器候选 | 用户能看懂“改前在哪里、改后在哪里”；不能只交组件树/API表 |
| F1 壳层与导航 | 按页布局能力、顶栏课题切换方案、子页与返回机制、创建表单分流；先接课题页验证 | 不丢全局入口、dirty、主题、滚动；其余页仍可用，分析不被误套布局 |
| F2 管理/详情分离 | 按文献→方案→记录逐页交付，包含对应空错态与窄屏 | 每页独立走通管理→详情→操作→返回后再进下一页；不积攒七页到最后一起验 |
| F3 知识前端交付 | 容器组件与同源列表承载、继续积累/审阅工作区、阅读定位桥接、迹芽素材与状态展示接口 | 填真实 E6.4 前端交付列：模块、路由、挂载、事件、尺寸与主题；占位不记E6完成 |
| E6-B 联合接入 | 用户确认前端停点满足后，与知识实施方完成真实数据/事件、来源、人审、快照等集成 | 按合同 T36–T40、E6.5 子用例及浏览器路线验收，不能用设计稿代替 |
| F4 对话 | 会话管理、范围选择、聊天主体与辅助区 | 保留固定输入快照、引用与人工采纳；地图复用经实际接线确认 |
| F5 全站回归 | 双主题、窄屏、键盘、返回/滚动/dirty、后台任务与分析回归；缺口列表 | 用户路径实际走通，有问题如实列未完成，不以“页面看起来齐了”结案 |

F3 的前端准备不要求等 F4 才能交付；E6-B 能否恢复按既有停点单独确认。F0 的展示方案需先审阅，避免直到大范围改完才发现页面方向仍不对。

每阶段报告只回答：改了哪些页面、主要操作移到哪里、保留了什么、实际验证了什么、哪些没接上。不要把文件数量或组件数量当成用户价值。

## 7. 前端与 E6 的交接方式

以[最新 E6 交接](../../record/HANDOFF_E6.md)为背景，前端交付可挂载、可操作的页面部件与定位桥接，E6 集成负责把真实知识视图、固定引用和任务状态接进去。全局壳层/样式/导航由前端统一持有；双方修改同一入口文件前先约定归属，不各自重写一套总览。

接入表需要填的是实际成果，不是承诺：

| 项目 | 前端需要说明 |
| --- | --- |
| 页面入口 | 总览、继续积累、审阅、wiki、比较与快照的真实导航落点和返回目标 |
| 容器与列表 | 实际模块路径、挂载/卸载方式、选择/过滤/翻页事件、主题变量、聚合与空错态 |
| 阅读桥接 | 怎样接收指定附件、固定版本与定位信息；定位失败怎么显示；怎样返回原审阅项 |
| 审阅宿主 | 队列、原文、分项编辑如何承载；dirty、确认成功、冲突、改绑如何显示 |
| 流水线与素材 | 状态字段的真实对应关系；恢复任务方式；素材来源、静态降级与减少动态效果 |
| 并行编辑 | 当前基线、双方负责文件、合并先后、已知未接能力 |

不强制新文件必须叫 `knowledge-base.js`。现有模块重用或拆分由前端实现方案决定，但不另起独立展示站，不换整个框架，不维护第二份“假知识库”。

当前只读接口已有 `/api/knowledge/container` 与 `/api/knowledge/pipeline/:runId`（据 E6-A 交接）；本文未调用接口验证响应。实施接线时必须先核对真实入参/返回值，不从页面文案猜字段。旧比较入口的业务适配和容量复测仍属独立未闭环项，不能顺带塞进样式重构；固定版本口径据 S05-T9 已修正，不再当作尚待选择的方案。

## 8. 验收：用用户的一次操作检查，而不是数面板

前端评审至少逐条演示以下路径。这里是未来验收清单，**本稿没有执行这些浏览器测试**。

- [ ] 进入已有课题，第一眼能说明研究对象与下一步；课题切换一直可发现，其他课题目录不常驻占宽。
- [ ] 在文献管理找到一篇文献→阅读→右侧调出库→换篇→回到原管理筛选和位置；阅读页无常驻导入表单。
- [ ] 从知识元素进入详情→核对条件→查指定原文→返回同一元素/审阅项；历史不可用时不自动换新来源。
- [ ] 空知识库有真实空态；有数据时容器和列表同范围同计数；筛选无结果、加载失败和未接线三个状态可区分。
- [ ] 从总览进入知识目录并回查来源；选择两个操作数进入比较，能区分可计算、仅并列和阻断原因；返回保留选择。
- [ ] 预览当前范围→冻结成功→查看历史快照→导出→返回当前；冻结失败、视图过期与来源权限拒绝有真实反馈，不假报成功。
- [ ] 从继续积累发起已授权的合成/模拟任务→查看真实状态→分项审阅→确认成功后归入；刷新不重复计数，关动画仍能完成。
- [ ] 方案管理→单方案图→节点详情→编辑/取消→返回，期间没有被“新建方案”表单挤占主体。
- [ ] 记录总览→执行→数据表或样品→返回；宽表可用，录入中后台更新不会清空内容。
- [ ] 会话管理→选范围→聊天→查引用→返回；上翻历史不被新消息拉走，采纳前可核对目标。
- [ ] 至少在切页、切课题、换对象、关闭面板、浏览器返回五种离开方式检查未保存保护；保存失败保留输入。
- [ ] 双主题、窄屏、200%缩放、键盘与减少动态效果均走通核心路径；分析旧流程不退化。

实现验收使用隔离合成材料、已授权的实例与调用方式；不得覆盖/重启现用实例 `5184/5187/5191`，不得读取密钥或私有测试材料充当公开样本。浏览器按项目约定用 Edge；截图由用户负责。运行测试、启动服务、真实模型、提交/推送/合并各按当时有效授权，不从本指南自动获得许可。

## 9. 可直接复制给前端 Agent 的启动提示词

> 你负责 LOCUS 的前端体验重构，不负责重写业务系统。请先阅读本指南及知识库执行合同 E6、最新 E6 交接，再检查现有页面。当前任务先交付 F0 体验方案，不改应用代码、不启动服务、不提交。
>
> 从研究者任务出发设计：管理页找对象，详情页看当前对象，编辑态修改对象，审阅页核对证据。不要把同一套多栏模板复制七次，也不要把“少几栏”当成果。把常驻的新建/导入表单移到管理入口或按需流程，给主要内容让位。
>
> 保留书脊与宣纸/光卷品牌、已有功能和保护机制。课题切换建议常驻顶栏；文献右侧建议仅作为阅读时拉出的库；两点须在方案中标为待用户确认。知识最终以真实大容器为主页面核心，并提供同源列表；石榴只是候选外形。迹芽表达积累过程，但审阅必须有普通列表、原文核对、明确按钮和键盘入口。分析本轮不重新设计。
>
