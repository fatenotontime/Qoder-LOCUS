## 4 影响链专项验收

| 编号 | 变更/场景 | 必须观察到 |
|---|---|---|
| I-V01 | 改确认表中一个数值 | 正确定位有关分析、图表、数值及报告块，给出依赖路径 |

| I-V04 | 修改方法、参数或代码 | 新运行与新产物，旧运行可还原，不覆盖旧报告 |
| I-V05 | 改研究目标或判定标准 | 解释/结论复核，已有数值不必无理由重算 |
| I-V06 | 撤回文献证据/排除样品 | 所有相关下游判断触发复核，排除原因可查 |
| I-V07 | 新数据v3替代v2 | v2/A/G/P历史仍可复现；最新界面明确过期/待复核 |
| I-V08 | 一个结果被多个报告复用 | 所有依赖者可找到；不遗漏非当前打开的报告 |
| I-V09 | AI上下文含材料但引用不明确 | 保存上下文快照，保守复核，不伪称精确语义影响 |
| I-V10 | 人工改写报告块 | 来源链接保留，支持关系待确认，不自动判可信 |
| I-V11 | 人工确认无需重算 | 记录确认人、理由、变更版本；下一次变更重新判断 |
| I-V12 | Word/包导出与外部编辑 | 快照附依赖索引/复核状态，外部修改不冒充已审计 |
| I-V13 | 缺失依赖或删除引用对象 | 明确暴露缺口或阻止发布，不能当作无影响 |

状态名称、图结构、传播事务、API、细粒度定位与并发实现由Qoder提案；此处是行为契约，不提前钉死技术栈。完成标志是变更测试通过，不是画出一张依赖图。

## 5 公开样本验收

S01 至少选一条来源一致的完整小案例，逐项核查实验记录、原始数据、处理方法、成果、许可/例外、可访问性和最小文件体积。不能把不同研究随意拼成一个真实批次。

S02 优先调查ONS溶解度的原始实验链及OSM Series1的一条合成/表征链。ONS原数据/正文/网页许可分开记录；OSM默认项目许可不免除附件例外检查。档案取回失败如实记录。

S03 若用合成图片演示OCR，显示“合成示例”；若由公开文章反向重构方案，显示“重构方案，非原始记录”；若缺原始数据则明确功能演示边界，不能宣称全链复现。

S04 原始开放数值不自动当金标准。至少人工核验一个计算或来源对应；错误/撤回例可用于影响链演示但保留原标记。不得演示真实SRTP进度、数据、导师材料或个人身份信息。

## 7 Qoder 阶段任务与交付顺序

1. 盘点：确认新项目路径、其AGENTS、旧代码只读输入范围和现存改动；建立结构化知识库。交付功能/依赖/继承需求/失败证据，不读私人数据探索代码。
2. 环境：回填本文件第1至3节，用独立公开/合成材料验证；不得省略三项完整产出。若需对外部署，在执行前说明影响并由用户确认。
3. 核心设计：交付对象/字段字典、关系、版本状态规则、API与Agent Runtime提案、ADR；将已确认与待决明确分开。
4. 公开样本：完成许可与全链清单，再确定首个分析任务；不因方便使用SRTP。
5. 端到端：公开课题→证据→方案/图→执行与样品→识别确认→分析验证→可追溯初稿/导出；模型失效仍保留非模型工作。
6. 影响链：完成第4节回归与人工复核闭环，再宣称可追溯；不能只验证正常生成路径。
7. 竞赛材料：五步以内访客路径、Qoder过程/截图/人改记录、测试证据、限制与已知问题、论坛材料。范围冻结由实际验收驱动，不为所有远期想法承诺日期。

每阶段保留Git提交、prompts、模型版本、diff、测试、人工干预和ADR。禁止将敏感输入/模型原始响应复制进项目记忆或公开Git；业务审计原始响应保存在授权业务数据区，与开发证据脱敏副本分开。
